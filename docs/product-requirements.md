# ThunderLedger 产品需求文档

## 1. 文档状态

- 版本：v1.0（批次 0 基线）
- 风险等级：L2
- 当前阶段：需求与架构冻结，暂不实现业务功能
- 技术基线：Vue 3 + Vite + TypeScript、Fastify、PostgreSQL、Cloudflare R2

## 2. 背景与目标

用户在闲鱼、微博等二手平台经营商品时，需要同时管理库存、图片、上架价格、成交记录和费用。个人售卖容易混淆；与朋友共同采购和售卖时，还需要记录出资、销售归属、邮费垫付，并在批次结束时自动算清双方应收应付。

ThunderLedger 的目标是提供一个可追溯的个人经营账本，并以协作批次支持多人共同售卖。系统优先保证数据准确、权限明确和结算可解释，再逐步扩展为可插拔的平台产品。

## 3. 范围

### 3.1 首期范围

- 用户账户、邀请注册和登录。
- 个人空间、协作空间、成员角色和批次参与人。
- 商品资料、图片上传/复用、封面和库存批次。
- 手工记录上架渠道、链接、价格和状态。
- 销售、收款人、销售人和直接费用。
- 共同采购批次、参与人出资、商品成本分摊和结算单。
- 审计记录、基础报表和 CSV 导出。

### 3.2 非目标

- 首期不自动同步闲鱼、微博订单。
- 首期不接入支付、物流、自动抓图或平台账号托管。
- 不提前拆分微服务、消息队列或高并发基础设施。
- 不实现未提出的商品、订单、库存或收益规则。

## 4. 核心概念

| 概念 | 定义 |
|---|---|
| 用户 User | 可登录平台的账户。 |
| 经营空间 Workspace | 长期存在的个人或团队经营容器，不等于一批商品。 |
| 商品 Product | 可复用的商品资料和图片集合。 |
| 库存批次 InventoryLot | 某商品在某次采购/协作批次中的数量和成本。 |
| 协作批次 CollaborationBatch | 一次共同采购和共同售卖的账务主体。 |
| 批次参与人 BatchParticipant | 对某个批次拥有数据权限并参与出资、销售或结算的用户。 |
| 上架 Listing | 商品在某渠道的展示记录。首期为手工渠道。 |
| 销售 Sale | 实际成交记录，包含销售人、收款人和成交价。 |
| 费用 Expense | 邮费等直接费用，包含支付人和关联销售。 |
| 结算 Settlement | 对指定批次已发生销售和费用的最终核算快照。 |

空间是长期容器，批次负责隔离具体业务。相同商品可以在个人批次和共同批次中分别存在。

## 5. 功能需求

### 5.1 账户与访问控制

- 用户由空间所有者邀请注册；邀请应有过期时间和一次性使用约束。
- 每个用户自动拥有一个个人空间。
- 空间角色为所有者、管理员、编辑者、查看者。
- 批次单独维护参与人范围；只有批次参与人能读取批次内财务和库存数据。
- 单条记录可标记为私有；私有记录仅创建者可见。
- API 必须在服务端执行空间、批次和记录级权限校验；前端隐藏按钮不构成授权。

### 5.2 商品、图片与库存

- 商品支持名称、描述、参考价格、图片列表和封面。
- 图片使用 R2 私有资源，支持上传、复用、签名 URL 和软删除。
- 库存默认按数量管理；需要逐件追踪时支持单件明细。
- 库存批次必须关联商品和协作批次（个人批次也视为批次）。
- 每次入库、售出、作废或调整都产生库存变更记录。
- 商品成本按批次记录；同一商品在不同批次中成本相互独立。

### 5.3 上架、销售与费用

- 上架记录包含渠道名称、外部链接、展示价格、状态和上下架时间。
- 销售记录包含商品/库存批次、成交价、销售人、收款人、成交时间和备注。
- 同一批次允许不同成员以不同价格销售。
- 销售收入进入批次公共收入池，不按销售人直接归属最终收益。
- 费用记录包含类型、金额、支付人、关联销售和发生时间。
- 首期渠道为手工录入；渠道接口必须保留未来同步能力。

### 5.4 协作批次与结算

- 批次记录采购总额、采购日期、状态、参与人和结算规则。
- 每位参与人记录实际出资金额；出资合计必须等于采购总额。
- 每个商品记录成本分摊；分摊合计必须等于采购总额。
- 收益分配比例默认按出资比例，可单独调整并记录原因。
- 邮费等直接费用先返还给实际垫付人。
- 结算支持预览和确认；确认后生成不可变快照。
- 锁定后的数据不得直接覆盖，只能追加调整单。
- 未售库存不进入锁定结算；商品售出或明确作废后才可完成批次结算。

#### 结算口径

完整批次的计算为：

```text
利润 = 销售总额 - 已售商品成本 - 直接费用
参与人利润份额 = 利润 × 收益分配比例
参与人当前净额 = 已收销售款 - 已垫付费用 - 已支付采购出资
结算转账额 = 参与人利润份额 - 参与人当前净额
```

销售人只影响已收销售款的记录，不改变公共收入池的收益分配。完整批次结算时，所有参与人的结算转账额合计必须为零。

示例：A、B 各出资 250 元；A 售出 300 元并垫付邮费 20 元；B 售出 400 元并垫付邮费 10 元。销售额和利润均按 50%/50% 分配，结算应由 B 向 A 转账 55 元。

### 5.5 台账、审计与报表

- 财务流水采用追加记录方式，修改通过冲正或调整记录完成。
- 记录权限变更、邀请、出资、销售、费用、结算确认和调整操作。
- 提供库存、销售、利润、成员贡献和待结算概览。
- 导出必须沿用 API 的数据权限范围。

## 6. 权限矩阵

| 操作 | 所有者 | 管理员 | 编辑者 | 查看者 |
|---|---:|---:|---:|---:|
| 查看有权批次 | 是 | 是 | 是 | 是 |
| 创建/编辑商品、库存、上架、销售、费用 | 是 | 是 | 是 | 否 |
| 管理成员和角色 | 是 | 是 | 否 | 否 |
| 创建和关闭批次 | 是 | 是 | 按空间策略 | 否 |
| 调整收益比例 | 是 | 是 | 否 | 否 |
| 确认并锁定结算 | 是 | 是 | 否 | 否 |
| 查看审计记录 | 是 | 是 | 否 | 否 |
| 删除数据 | 仅软删除 | 仅软删除 | 仅软删除本人可编辑记录 | 否 |

以上角色权限仍受批次参与人范围和私有标记限制。

## 7. 金额、时间与数据不变量

- 金额精确到 0.1 元，数据库使用整数“角”存储，API 使用金额字符串。
- 超过 1 位小数直接拒绝，不自动四舍五入。
- 时间统一保存 UTC 或带时区时间，界面按 Asia/Shanghai 展示。
- 出资合计 = 采购总额。
- 成本分摊合计 = 采购总额。
- 售出数量不得超过可售库存。
- 锁定结算不得被普通更新覆盖。
- 所有查询必须带入用户、空间和批次范围。

## 8. 验收标准

- 用户 A 无法读取用户 B 的个人批次和私有记录。
- 协作空间成员按角色和批次参与人获得准确权限。
- 同一种商品在个人批次和共同批次中库存、成本和销售互不混淆。
- A、B 各出资 250 元时，无论谁以何种价格卖出，销售收入按约定比例进入公共池分配。
- 不同收款人、不同成交价和不同邮费均能正确生成结算转账额。
- 完整批次结算转账额总和为零。
- 结算锁定后普通编辑不改变历史结果，调整单可追溯。
- 图片上传、复用、签名访问和删除均受权限控制。
- 财务和权限关键操作均有审计记录。

## 9. 后续变更规则

本需求文档是批次 0 基线。涉及结算口径、权限边界、金额精度、数据删除或外部平台写操作的变更，必须先更新设计记录和测试计划，再进入实现。
