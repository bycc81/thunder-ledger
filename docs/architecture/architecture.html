ThunderLedger 总体架构

模块化单体：空间负责长期边界，批次负责协作和账务边界。

批次 0 基线Vue + Fastify + PostgreSQL + R2L2

架构决策

模块化单体首期不拆微服务，不引入消息队列。
空间 + 批次空间长期复用，批次隔离参与人和账务。
渠道可插拔首期手工渠道，未来通过 ChannelAdapter 扩展。

系统上下文

个人用户 / 协作成员登录、录入、结算确认
Vue 管理工作台 → Fastify API统一鉴权、数据范围和业务接口
PostgreSQL + Cloudflare R2业务事实与私有图片资源

接口与演进

ChannelAdapter

interface ChannelAdapter {
  id: string;
  capabilities: string[];
  createListing(input): Promise<AdapterResult>;
  importSales(cursor): Promise<NormalizedSale[]>;
  mapStatus(status): string;
}

数据约束

  • 金额精确到 0.1 元，存整数“角”。
  • 出资和成本分摊合计等于采购总额。
  • 售出数量不得超过可售库存。
  • 锁定结算只能通过调整单修正。
  • 外部渠道授权不进入核心台账表。

安全边界

前端隐藏按钮不等于授权；API 必须校验用户、空间、批次和私有记录范围。财务、权限和结算确认写入审计日志；删除采用软删除。
