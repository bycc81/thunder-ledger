# 变更设计记录

## 结论

用 2-4 句话说明推荐方案、是否进入实现、是否需要用户确认。

## 风险等级

`L0` / `L1` / `L2`，并说明判断理由。

## 产品与 UX 输入

新模块、新页面或明显改变用户操作路径的前端任务必须填写；普通后端或已有页面小修写“本轮不适用”。

- 产品定义：`product-brief.md`
- UX/UI 规格：`ux-spec.md`
- HTML 原型：`prototype/index.html`
- 产品确认状态：待确认 / 已确认
- UX 与原型确认状态：待确认 / 已确认
- 技术设计不得重新定义已确认的用户流程、页面主操作或关键交互；如需改变，先回到产品与 UX 阶段更新并重新确认。

## 背景与目标

说明当前问题和要达成的结果。

## 非目标

明确本次不做什么，防止范围扩大。

## 当前实现与缺口

列出现有模块、接口、表结构或页面，以及距离目标的差距。

## 方案与影响范围

说明实现方式、涉及的 API、页面、数据库、配置和部署内容。只写当前系统真实存在的组件。

## 风险、备份与回滚

说明认证、权限、数据准确性、隐私、迁移和部署风险，以及对应控制和回滚方式。

## 验收标准

列出正确结果、不能破坏的行为和验证方式。

## 开发任务绑定

新模块或新页面的每个开发任务必须绑定：

- 对应的产品/UX 条目或页面；
- 对应的 `Requirement + Scenario` 验收场景；
- 自动化验证或人工页面验收方式。
