# `data-ai-id` 语义化定位规范

## 目的

`data-ai-id` 是页面、自动化测试和 AI 页面分析之间的稳定定位契约。它帮助工具识别业务对象和操作，不承担样式、权限或可访问性职责。

## 命名规则

- 使用稳定的 ASCII kebab-case。
- 页面和区域使用业务语义，例如 `workspace-overview`、`recent-batches`。
- 重复项必须包含稳定业务 ID，例如 `batch-item-{batchId}`、`member-remove-{memberId}`。
- 不得把用户输入、随机数、时间戳或展示文案直接拼入 ID。
- ID 不用于 CSS 选择器、业务逻辑或权限判断。
- UI 改版必须保留已确认的业务 ID；确需变更时同步更新原型、注册表和自动化测试。

## 必须覆盖的节点

- 页面根节点和主要业务区域。
- 按钮、输入框、选择器、筛选器和导航项。
- 弹窗、Popup、全屏弹层的根节点及关闭/提交操作。
- 列表容器、重复列表项和列表项内的关键操作。
- 删除、移除等危险操作及其确认入口。

## 组件约定

- 公共 Vant 封装组件提供 `aiId?: string`，绑定到业务根节点。
- Teleport 类型组件将 ID 绑定到实际弹层根节点，而不是调用处的占位节点。
- 第三方组件内部装饰节点不强制添加；业务包装节点必须添加。
- `data-ai-id` 不替代 `role`、`aria-label`、键盘焦点和触控可访问性。

## 维护方式

- 通用规则维护在本文件。
- 每个页面/需求维护独立的 `data-ai-id-registry.md` 实例。
- 原型先登记 ID，页面实现复用相同 ID。
- 页面验收时扫描实现与注册表，确认无缺失、重复或不稳定 ID。
