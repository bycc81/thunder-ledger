# ThunderLedger 安全规范

本文是 ThunderLedger 的唯一正式安全规范，面向认证、API、数据库、文件资源、权限和财务数据。

## 必须遵守

- 密码、`DATABASE_URL`、`SESSION_SECRET`、JWT 密钥和 R2 凭据只从环境变量或云 Secret 注入。
- 生产环境不提交 `.env`，日志、错误响应和截图不得暴露凭据或完整用户隐私。
- API 使用 Helmet、受控 CORS、输入校验和参数化 ORM 查询。
- 登录密码使用 bcrypt 等单向哈希；会话令牌设置合理过期时间。
- 前端不把高权限令牌写入 `localStorage` 或 `sessionStorage`。
- 所有业务接口在服务端执行认证、角色、空间、批次和记录级权限校验。
- 删除采用软删除；财务、权限和结算操作写入审计日志。
- PostgreSQL 不暴露公网；生产服务只开放必要端口并启用 HTTPS。

## 数据与文件安全

- 用户手机号、地址、订单和其他隐私数据遵循最小展示原则。
- R2 使用私有 Bucket 和短时签名 URL，永久密钥不得交给浏览器。
- 文件上传校验 MIME、大小和对象 Key，禁止使用原始文件名作为路径。
- 外部 URL 访问必须阻止内网地址和云元数据地址，避免 SSRF。
- 导出、收益计算和权限修改必须记录操作者、范围和结果。
- 金额使用 0.1 元精度的整数“角”存储，避免浮点误差。

## 常见风险

- 防止 SQL 注入、XSS、CSRF、路径穿越和不安全文件上传。
- 不把前端按钮隐藏当作授权控制。
- 不在日志中记录密码、会话令牌、R2 密钥或完整敏感数据。
- 依赖和基础镜像定期更新；发现高危漏洞时记录影响并安排修复。

## 变更检查

涉及登录、权限、数据库结构、文件上传、导出或收益计算时，设计记录至少说明：

1. 谁可以执行，越权如何拒绝。
2. 输入、文件类型、大小和错误响应如何校验。
3. 数据如何保存、删除、备份和恢复。
4. 日志与审计如何避免泄露敏感信息。
5. 测试、回滚和残留风险是什么。

## 事件处理

发现密钥泄露、越权、数据误删或异常访问时，立即停止相关操作、轮换凭据、保留日志并评估影响；恢复前先确认备份和恢复方案。
