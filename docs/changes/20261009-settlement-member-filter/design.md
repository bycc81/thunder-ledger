# 创建账单：按批次人员筛选销售

日期：2026-10-09。风险等级：L1（已有页面局部筛选与选择交互）。

## 目标与范围

在创建账单的第一步，为“本次销售”增加人员复选框下拉筛选。候选项来自当前批次全部人员，按收款人 ID 匹配普通销售及快速售出。沿用现有账单草稿接口，不修改后端、权限、数据库和结算计算规则，也不改变三步创建流程。

## 交互与页面/API 契约

- 使用 Vant DropdownMenu / DropdownItem / CheckboxGroup / Checkbox，默认“全部人员”，未选人员表示不过滤。
- 人员选项直接使用 `GET /api/batches/:batchId/settlements/draft` 返回的 `members`，包含没有待结算销售的人员。
- 下拉框内多选为草稿，点击“确定”后应用；“重置”清空草稿，再确定恢复全部人员；关闭下拉框不应用未确认的修改。
- 多个人员按并集匹配普通销售及快速售出的 `sellerUserId`，不得按显示姓名匹配。
- 筛选只影响销售显示，保留已选销售；“全选 / 清空”仅添加 / 移除当前可见销售，隐藏销售的选择保持不变。
- 显示当前匹配笔数、总已选笔数及隐藏已选笔数，避免忽略仍会参与账单的销售。
- 无匹配时显示空态，下一步仍遵循现有至少选择一笔销售规则。费用仍按现有销售关联逻辑联动。
- 人员筛选不会限制第二步的利润分配人员，推荐与预览请求仍提交所有已选销售 ID。

## 验收

1. 默认显示全部可结算销售；下拉候选包含全部批次人员。
2. 单选、多选并集、重置、不确认关闭均正确；普通销售和快速售出一并筛选。
3. 无销售人员有空态；跨筛选全选、清空、隐藏选项保留与请求载荷正确。
4. 费用联动、返回第一步后的筛选与勾选保持正确。
5. 390×844、430×932 完成截图、交互及 `data-ai-id` 检查，无横向溢出和弹层底部操作遮挡。
6. 前端 typecheck/build；按用户要求，后端 typecheck/test 和草稿/推荐接口契约自测。无需启动正式前后端服务。
