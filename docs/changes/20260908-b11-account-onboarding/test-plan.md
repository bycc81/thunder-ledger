# B1.1 测试与验收计划：注册与账号管理

## 结论

本轮重点证明：只有受邀用户可注册；工作区管理员可安全添加新旧账号；系统账号管理与密码变更不造成越权或旧会话继续有效。

## 验收场景

1. owner/admin 邀请一个未注册用户名后，得到一次性注册链接；注册链接仅展示一次，页面不持久化凭证。
2. 新用户打开有效链接，用户名只读，设置两次一致的合规密码后注册，获得个人工作区并按邀请角色加入目标工作区；重复、过期、错误用户名或无效链接均失败。
3. owner/admin 输入已注册用户名并选择角色后，用户立即加入当前工作区；未知用户名、同工作区重复成员、viewer/editor 越权均被拒绝。
4. 系统管理员开通普通账号后可登录；普通用户不能访问账号管理；系统管理员不能停用自己或系统管理员账号。
5. 停用账号后登录被拒绝，恢复后可登录；停用、重置密码、本人改密码后，旧 JWT 在下一次请求均被拒绝。
6. 本人改密码必须提供正确当前密码；密码不合规、确认不一致均不改变密码。
7. API 响应、操作记录和页面不含密码、密码哈希或完整邀请凭证。

## 自动化验证

- 后端：`npm run typecheck`、`npm test`、`npm run db:check`；增加认证、邀请、账号管理、会话失效的接口测试。
- 前端：`npm run typecheck`、`npm run build`；扫描页面 `data-ai-id` 与注册表一致。
- 数据库：受控执行 `009_account_session_version`，确认已有用户会话版本默认为 0。
- 容器：`docker compose config`、`docker compose build`、`/api/healthz`、`/api/readyz`。

## 人工验收

1. 在开发环境用管理员账号依次验证邀请新账号、复制注册链接、注册、已有账号加入和角色展示。
2. 用系统管理员验证开通账号、停用/恢复和重置密码；再用普通账号确认看不到账号管理入口。
3. 在 390×844、430×932 检查注册、成员弹窗、修改密码和账号管理页面，无横向溢出、底部导航遮挡或不可点击控件。
4. 通过 `http://192.168.161.135:5174` 创建注册链接，确认“复制链接”可粘贴使用；如浏览器不授予剪贴板权限，确认可长按文本框手动复制。
5. 用普通账号登录并刷新“我的”，用户名保持实际用户名；用系统管理员登录并刷新“我的”，显示“账号管理”入口。

## 结果与残留风险

- 自动化验证：后端 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run db:check` 通过；前端 `npm.cmd run typecheck`、`npm.cmd run build` 通过；`docker compose config`、API/Web 容器构建、本地迁移、`/api/healthz` 与 `/api/readyz` 通过。无效注册链接预览接口返回 400，符合预期。修改密码、停用或重置后的旧令牌会连恢复登录状态接口一起被校验。
- 缺陷修复验证：受邀注册更新邀请状态时必须传入邀请编号；本次真实注册链接此前失败的事务已回滚，待修复部署后复测成功注册。
- 缺陷修复验证：已通过。启动时恢复当前登录信息，普通账号刷新后保持实际用户名，系统管理员刷新后显示账号管理入口。
- 人工验收：受邀注册、空间归属、添加已有账号、普通账号刷新用户名、系统管理员入口、账号停用/恢复、修改密码和旧登录状态失效均已通过。
- 残留风险：注册链接没有撤销入口；密码重置后的新密码仍需由管理员通过安全渠道传递，系统不发送邮件或短信。
