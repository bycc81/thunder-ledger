# 产品与 UX 定义：B1.1 注册与账号管理

## 结论与确认

在 B4 前补齐账号进入系统的完整路径：工作区管理员邀请新用户，受邀用户通过链接自行设置密码并注册；已注册用户可直接加入工作区；系统管理员可开通、停用、恢复和重置账号密码。系统不开放陌生人自由注册。原型位于 [prototype/index.html](prototype/index.html)，待用户确认页面结构、主流程和关键交互后进入技术设计。

## 用户、问题与范围

- 目标用户/角色：系统管理员、工作区所有者/管理员、受邀新用户、已注册用户。
- 使用场景与触发入口：管理员在“成员”页邀请或加入成员；系统管理员从“我的”进入“账号管理”；新用户打开邀请链接完成注册。
- 当前问题：后端已有邀请注册能力，但前端没有注册链接或注册页面；已注册账号不能直接加入工作区；无法在正式环境通过受控界面开通和管理账号。
- 产品目标：不用 SQL、不泄露密码或邀请凭证，让账号安全进入工作区，并让系统管理员完成必要的账号维护。
- 用户完成任务后的可观察结果：新用户注册后自动拥有个人工作区并加入受邀工作区；已有账号可立即成为工作区成员；系统管理员可安全开通、停用、恢复和重置账号密码。
- 本次做什么：注册链接、注册页、成员页的“邀请新账号/加入已有账号”、系统账号管理页、本人修改密码。
- 本次不做什么：开放注册、邮箱/短信发送、找回密码、删除账号、变更系统管理员、批量导入账号、多因素认证。

## 用户流程、规则与场景

### 用户主流程

~~~text
工作区管理员
  ├─ 成员 → 邀请新账号 → 选择角色 → 复制注册链接 → 新用户打开链接并设置密码 → 自动加入工作区
  └─ 成员 → 加入已有账号 → 输入用户名、选择角色 → 立即加入工作区

系统管理员
  └─ 我的 → 账号管理 → 开通账号 / 停用或恢复 / 重置密码

任意已登录账号
  └─ 我的 → 修改密码 → 验证当前密码 → 设置新密码
~~~

### 业务规则与权限

- 注册仅接受未过期、未使用的邀请链接；链接有效 7 天、仅能使用一次。链接使用后不能再次注册。
- 注册用户名由邀请锁定，只展示，不允许修改；密码需 8–64 位，并再次确认。注册链接中的凭证只放在 URL 片段中，浏览器不会把它发送给页面服务器。
- 工作区所有者/管理员可邀请新账号，也可按精确用户名加入已注册账号；编辑者和查看者只能查看成员。
- 系统账号管理页只对系统管理员可见和可操作。开通账号会同时建立该用户的个人工作区；账号管理页绝不展示密码或密码哈希。
- 停用账号后该账号不能继续登录；恢复后可重新登录。系统管理员不能停用自己或系统管理员账号。
- 系统管理员重置密码、用户修改自己的密码都要求输入新密码和确认密码；用户修改本人密码还必须验证当前密码。所有旧登录会话在下一次请求时失效。
- 所有开通、邀请、加入、停用、恢复、密码重置和修改密码写入操作记录；记录不保存密码、完整注册链接或邀请凭证。

### 需求场景

#### Requirement: 受邀注册

系统 SHALL 仅允许持有有效邀请链接的新用户注册，并在成功后自动加入邀请对应工作区。

#### Scenario: 新用户加入协作工作区

- **WHEN** 管理员邀请 `dandan` 并把注册链接发给对方，`dandan` 在有效期内设置符合规则的密码
- **THEN** 系统创建 `dandan` 的账号和个人工作区，并把 `dandan` 按邀请角色加入目标工作区；同一链接不能再次使用

#### Requirement: 已有账号加入成员

系统 SHALL 让工作区管理员按用户名把已注册账号直接加入当前工作区，并选择工作区角色。

#### Scenario: 已注册用户加入当前工作区

- **WHEN** 工作区管理员输入已有用户名 `follow`，选择“编辑者”并确认
- **THEN** `follow` 立即出现在成员列表中；没有同名账号时显示“未找到已注册账号”

#### Requirement: 系统账号管理

系统 SHALL 仅允许系统管理员开通、停用、恢复和重置普通账号。

#### Scenario: 系统管理员开通账号

- **WHEN** 系统管理员填写用户名、初始密码和确认密码并提交
- **THEN** 系统创建可登录账号及个人工作区，不展示或记录该密码明文

## 页面与交互规格

### 页面地图

~~~text
登录页
  └─ 注册页（邀请链接）

成员页
  └─ 添加成员
      ├─ 邀请新账号 → 注册链接结果
      └─ 加入已有账号

我的
  ├─ 修改密码
  └─ 账号管理（仅系统管理员）
      ├─ 账号列表
      ├─ 开通账号
      └─ 停用/恢复/重置密码
~~~

### 注册页

- 核心任务：受邀用户确认用户名并设置自己的密码。
- 进入条件：打开注册链接；无效或过期链接显示说明和“返回登录”。
- 信息层级：邀请说明 → 锁定用户名 → 密码与确认 → 注册按钮。
- 主操作：完成注册并前往登录。
- 次要操作：返回登录。

### 成员页的添加成员弹窗

- 核心任务：根据对象是否已有账号选择合适方式。
- 信息层级：方式选择 → 用户名与角色 → 提交结果。
- 主操作：创建注册链接或直接加入成员。
- 次要操作：复制注册链接；关闭弹窗。

### 账号管理页

- 核心任务：系统管理员查看账号状态并进行受控维护。
- 信息层级：账号列表 → 开通账号 → 单个账号的更多操作。
- 主操作：开通账号。
- 危险操作：停用账号需二次确认；恢复与重置密码不显示旧密码。

### 我的：账户操作

- 核心任务：本人修改密码；系统管理员进入账号管理。
- 主操作：修改密码。

## 状态、响应式与验收

| 状态 | 页面表现 | 可执行操作 |
|---|---|---|
| Loading | 注册链接、账号列表或提交按钮显示加载 | 禁止重复提交 |
| Empty | 账号管理无普通账号时显示空状态 | 可开通账号 |
| Error | 显示链接无效、用户名不存在或密码校验错误 | 修正输入、重新提交或返回登录 |
| 无权限 | 非系统管理员不显示账号管理入口；接口返回拒绝 | 无 |
| Disabled | 停用后的账号状态明确；不可停用自己或系统管理员 | 可恢复普通停用账号 |
| Success | Toast 和列表刷新；注册链接只显示一次 | 继续复制链接或返回 |

- 目标视口：390×844、430×932；单列字段，触控目标至少 44px。
- 复用：现有登录页、成员页、我的页、MobileShell、Vant Dialog/Popup/Picker/Field/Button/Cell。
- 视觉方向：账号状态用“正常/已停用”文字和颜色同时表示；密码输入不出现在列表、操作记录或截图提示中。
- 原型：[prototype/index.html](prototype/index.html)。

### 页面验收

- [ ] 管理员能在成员页清楚选择“邀请新账号”或“加入已有账号”
- [ ] 新用户能从注册链接完成注册，过期链接有明确反馈
- [ ] 系统管理员能开通、停用、恢复和重置普通账号，且不能操作自己或系统管理员账号
- [ ] 已登录用户能验证当前密码后修改自己的密码
- [ ] 密码和邀请凭证不在结果页、操作记录或错误提示中出现
- [ ] 原型的关键业务节点已登记稳定 `data-ai-id`
- [ ] 用户已直接打开原型确认页面结构、主流程和关键交互
