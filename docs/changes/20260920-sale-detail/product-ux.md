# 产品与 UX 定义：销售详情

## 结论与确认

推荐新增独立的移动端只读“销售详情”页。用户从交易页点击整条销售记录进入，查看成交、手续费、实际收款、成本、关联其他费用、备注与结算状态；撤销仍是交易列表中的独立危险操作，不在详情页提供编辑或删除。

可运行原型位于 [prototype/index.html](prototype/index.html)。本文件与原型等待确认；确认页面结构、字段和跳转关系后，才进入技术设计和 Vue/API 实现。

## 用户、问题与范围

- 目标用户/角色：可读取当前批次的 owner、editor、viewer；其中 owner/editor 可以在交易列表发起未结账销售的撤销。
- 使用场景与触发入口：用户在批次的“交易 > 销售”列表中核对一笔已录入的销售，点击销售记录。
- 当前问题：列表只展示商品、售价、卖出人、实收、手续费和时间，无法追溯备注、成本、关联费用、撤销原因和结算归属。
- 产品目标：一页清晰说明单笔销售的收款、成本和状态事实，使结算前后的记录均可追溯。
- 可观察结果：用户能从销售列表进入详情，查明手续费如何计算、实际收款归属、关联费用和是否已经结账；已结账销售可进入对应账单。
- 本次做什么：销售详情只读页面、销售列表进入入口、单笔只读查询，以及从详情进入已确认账单的链接。
- 本次不做什么：编辑销售、删除销售、在详情页发起撤销、修改手续费规则、修改结算规则、费用详情页和外部订单同步。

## 用户流程、规则与场景

### 用户主流程

```text
批次详情 → 交易 → 销售列表 → 点击销售记录 → 销售详情
  ├─ 未结账 / 已撤销：查看记录事实，返回交易列表
  └─ 已结账：查看账单状态 → 打开对应账单详情 → 返回销售详情或结算列表
```

### 业务规则与权限

- 仅有当前批次读取权限的用户可以查看销售详情；服务端继续使用批次权限校验，未授权资源按现有策略返回 `404`。
- 详情是已保存事实的只读呈现。销售会影响库存、成本账本及结算，不能在详情中直接编辑或删除。
- 已撤销销售展示“已撤销”、撤销原因与撤销时间；不展示“关联其他费用”中的已撤销费用。
- 已结账销售展示“已结账”并提供账单入口；不存在可编辑或撤销入口。
- 未结账且未撤销的销售展示“待结账”；详情页不放撤销按钮，交易列表保留独立的“撤销”入口及二次确认。
- “实际收款”恒等于成交总价减平台手续费，收款归属为卖出人；详情显示事实，不重新计算或分配收益。
- 关联其他费用仅包含当前批次中 `saleId` 等于本销售 ID 的费用。费用已撤销时仍可显示其历史状态，但不计入该销售的“有效关联费用”汇总。

### 需求场景

#### Requirement：可追溯的销售详情

系统 SHALL 允许拥有当前批次读取权限的用户从销售列表打开任意销售记录，并查看其成交、手续费、实际收款、成本、关联其他费用、备注和状态事实。

#### Scenario：核对闲鱼销售手续费

- **WHEN** 用户点击一笔销售渠道为“闲鱼”、手续费比例为 1.60% 的销售记录
- **THEN** 详情显示成交总价、渠道、`按比例 1.60%`、平台手续费、实际收款、卖出人和成交时间，且实际收款等于成交总价减平台手续费。

#### Requirement：已结账销售可追溯账单

系统 SHALL 为已结账销售显示结账状态并提供对应已确认账单的只读入口。

#### Scenario：查看已结账销售

- **WHEN** 用户打开一笔已结账销售
- **THEN** 页面显示“已结账”和确认时间（若接口提供），用户点击账单入口后进入该批次下的对应账单详情。

#### Requirement：危险更正与详情分离

系统 SHALL 不在销售详情页提供编辑、删除或撤销操作。

#### Scenario：查看待结账销售

- **WHEN** owner 或 editor 打开一笔待结账销售
- **THEN** 页面只显示“待结账”和返回交易列表入口；用户如需更正，必须回到交易列表使用现有“撤销”流程并填写原因。

## 页面与交互规格

### 页面地图

```text
批次详情
  └─ 交易
      └─ 销售列表
          └─ 销售详情（新增，只读）
              └─ 已确认账单详情（已结账时）
```

### 销售详情页

- 核心任务：核对一笔销售的全部已保存事实与结算归属。
- 进入条件：用户已登录且可读取当前批次；URL 包含批次 ID 与销售 ID。
- 离开/下一步：左上角“返回”回到交易列表；已结账时可进入账单详情。
- 信息层级：状态与商品摘要 → 收款与手续费 → 成本 → 关联其他费用 → 备注/撤销信息 → 账单入口。
- 主操作：已结账时“查看账单”。
- 次要操作：返回交易列表。
- 危险操作：无；撤销保留在交易列表中。

#### 关键字段与控件

| 区域 | 字段/控件 | 控件类型 | 必填/可选 | 说明 |
|---|---|---|---|---|
| 顶部 | 返回交易 | 导航按钮 | 必填 | 返回 `/batches/:batchId/transactions` |
| 摘要 | 状态、商品、数量、成交总价 | 展示 | 必填 | 状态为待结账、已结账或已撤销 |
| 收款 | 成交总价、平台手续费、实际收款、卖出人、渠道、成交时间 | 展示 | 渠道可空 | 比例手续费显示费率；固定手续费显示金额 |
| 成本 | 销售成本、销售毛利（未扣其他费用） | 展示 | 必填 | 毛利=成交总价－平台手续费－销售成本 |
| 关联其他费用 | 名称、付款人、金额、发生时间、状态 | 列表 | 可空 | 仅销售关联费用；保留已撤销费用的状态事实 |
| 备注 | 备注文本 | 展示 | 可空 | 空值显示“无备注” |
| 撤销信息 | 原因、撤销时间 | 展示 | 条件显示 | 仅已撤销销售显示 |
| 账单 | 查看账单 | 链接按钮 | 条件显示 | 仅已结账销售显示 |

### 交互与反馈

- 交易列表整条销售记录可点击，右侧“撤销”按钮阻止列表跳转，仅打开原有撤销确认。
- 详情加载中显示 Loading；请求失败显示错误与“重试”；资源不存在或无读取权限显示现有空/无权反馈并提供返回交易列表。
- 已结账但账单记录不可读取时，隐藏账单入口并提示“账单详情不可访问”。
- 不新增表单、弹窗或保存状态；状态标记同时使用文字与颜色。

## 状态、响应式与验收

| 状态 | 页面表现 | 可执行操作 |
|---|---|---|
| Loading | 页面主体 Loading | 返回 |
| Error | 错误说明与重试按钮 | 重试、返回 |
| 无权限/不存在 | 无权/不存在说明 | 返回交易列表 |
| 待结账 | 展示“待结账”状态 | 返回 |
| 已结账 | 展示“已结账”与账单入口 | 查看账单、返回 |
| 已撤销 | 展示“已撤销”、原因和时间 | 返回 |

- 移动端：以 390×844 和 430×932 视口验收，无横向溢出；金额右对齐，长商品名和备注可换行。
- 触控与焦点：返回和账单入口最小 44px，列表入口可键盘聚焦；状态不可仅依赖颜色。
- 复用：Vant `NavBar`、`Cell`、`Tag`、`Empty`、`Loading`；视觉风格沿用交易和账单详情页。
- 禁止模式：不做白底悬浮操作、不在详情页显示编辑/删除、不用一整页大卡片堆叠。
- 原型：[prototype/index.html](prototype/index.html)

### 页面验收

- [ ] 用户可从销售列表点击非操作区域进入对应销售详情。
- [ ] 详情准确展示手续费计算方式、实际收款、卖出人、成本和备注。
- [ ] 有关联费用、无关联费用及关联费用已撤销三种状态可辨。
- [ ] 待结账、已结账、已撤销三种状态可辨；只有已结账销售有账单入口。
- [ ] 列表的“撤销”继续独立工作，不因行点击而触发跳转。
- [ ] 关键业务节点具有稳定的 `data-ai-id`。
- [ ] 用户已打开原型确认结构、主流程和关键交互。
