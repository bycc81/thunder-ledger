# 测试与验收计划：销售详情

## 结论

证明销售详情只读取既有事实，能在正确权限和批次范围内展示，并且不会修改库存、手续费、成本或结算数据。

## 验收场景

1. 待结账销售：进入详情后，成交总价、手续费、实际收款、卖出人、成本、毛利、渠道、备注与列表/API 一致；不显示账单入口。
2. 比例手续费：销售总价 ¥300、手续费比例 1.60% 时，显示手续费 ¥4.80、实际收款 ¥295.20、毛利为总价减手续费减销售成本。
3. 固定手续费：显示“按金额”和固定手续费；无渠道/无手续费字段显示为“未填写”/¥0.00，不出现错误费率。
4. 关联其他费用：展示关联本销售的费用；无关联费用显示空状态；已撤销关联费用显示撤销状态与原因，且不改销售金额。
5. 已结账销售：展示“已结账”和账单入口，跳转至正确账单详情。
6. 已撤销销售：展示“已撤销”、撤销原因和时间，不提供账单入口或写操作。
7. 交互隔离：点击列表销售行进入详情；点击“撤销”只打开撤销确认，不跳转详情；键盘 Enter 可打开详情。
8. 权限与范围：viewer 可读取自己可读批次的详情；不属于该批次的销售 ID、无权限销售 ID 和不存在 ID 返回 404 且不泄漏字段。
9. 回归：读取详情前后比对销售、费用、库存可卖数量和账单金额，均不发生变化。

## 自动化验证

- 后端：在 `apps/backend` 运行 `npm run typecheck`、`npm test`；补充单笔销售读取、跨批次 404、无权限 404、已结账关联及撤销记录的测试。
- 前端：在 `apps/web` 运行 `npm run typecheck`、`npm run build`。
- 数据库：本变更无迁移，不运行迁移；用只读查询对比读取前后业务事实。

## 人工验收

1. 使用 390×844 与 430×932 视口登录可读账号，进入“批次 → 交易 → 销售”。
2. 依次打开待结账、已结账、已撤销销售，检查字段、状态、空状态与账单跳转。
3. 在可编辑账号下点击一笔未结账销售右侧“撤销”，确认仅出现原有二次确认；取消后销售详情和数据均不变。
4. 在 viewer 账号下打开详情，确认不存在编辑、删除、撤销入口。
5. 检查 `data-ai-id-registry.md` 列出的关键节点可定位，页面没有横向溢出或底部导航遮挡。

## 结果与残留风险

- 已通过：后端 `npm run typecheck`、`npm test`；前端 `npm run typecheck`、`npm run build`；`git diff --check`；重建 Docker API 后 `/api/healthz` 与 `/api/readyz` 返回正常。
- 已验证边界：详情 API 的路由实现复用批次只读权限、限制 `batchId + saleId`，且非法销售 ID 直接返回 `404`；接口代码不含写入 SQL、成本重算或审计写入。
- 未验证项：当前没有可复用的已登录浏览器会话，尚未完成真实销售、关联费用、已结账账单跳转和移动端截图的端到端验收。
- 残留风险：销售行与撤销按钮的实际点击隔离、详情的真实数据呈现仍需在登录态移动端页面手工确认。
