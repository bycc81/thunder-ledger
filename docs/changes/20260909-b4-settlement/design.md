# B4 协作台账与结算：设计记录

## 结论

按已确认的 [产品与 UX 定义](product-ux.md) 和 [HTML 原型](prototype/index.html) 实现阶段账单。后端以确认时的不可变快照、销售唯一锁定和单一数据库事务保证数据准确；移动端严格复用原型的三步流程与文案，不新增支付、撤销或批次关闭能力。本地开发可直接进入实现，无生产发布或不可逆数据操作。

## 风险等级

`L2`。本功能新增数据库结构、锁定销售记录并计算成本、利润、应收应付及转账建议；确认后的账单不可直接修改。

## 产品与 UX 输入

- 产品与 UX 定义：`product-ux.md`
- HTML 原型：`prototype/index.html`
- 产品确认状态：已确认
- UX 与原型确认状态：已确认
- 本设计只落实页面、API、数据和权限契约，不改变已确认流程、主操作或交互。

## 背景与目标

现有批次已具备采购、销售、费用与撤销记录，但无法把部分已售商品形成可解释且不可重复计算的阶段账单。本次让有管理权的用户选择当前未结账销售、纳入费用、确认成本和利润比例后生成锁定账单；所有有批次读取权的成员可查看已确认结果。

## 非目标

- 不执行支付或实际转账，不接平台订单。
- 不关闭批次、不结算未售库存、不撤销已确认账单。
- 不新增长期利润比例设置、报表导出或调整记录。

## 当前实现与缺口

- `sales` 已记录销售金额、卖出人和单笔消耗成本，`sale_reversals` 保存撤销。
- `expenses` 已记录费用、付款人和可选关联销售，`expense_reversals` 保存撤销。
- `inventory_purchases` 与 `purchase_cost_shares` 已记录采购付款人和采购成本承担。
- 当前没有账单实体、销售结账锁定、确认快照或结算页面/API。

### 操作与接口边界

| 操作 | 入口 ID | 前置条件 | 领域动作或接口 | 成功结果 | 失败反馈 | 是否二次确认 |
|---|---|---|---|---|---|---|
| 读取结算首页 | `settlement-page` | 具有批次读取权 | `GET /batches/:batchId/settlements` | 显示未结账数与确认列表 | 加载失败，可重试 | 否 |
| 获取可结算草稿 | `settlement-start` | 结算管理权 | `GET /batches/:batchId/settlements/draft` | 显示未撤销、未锁定销售和可用费用 | 无可结算销售显示空状态 | 否 |
| 计算预览 | `settlement-preview` | 选中至少一笔销售、字段通过前端基础校验 | `POST /batches/:batchId/settlements/preview` | 返回服务器计算的汇总、成员结果和建议 | 字段/状态改变时显示接口消息 | 否 |
| 确认账单 | `settlement-confirm` | 预览参数仍有效、用户确认锁定提示 | `POST /batches/:batchId/settlements` | 写入账单快照并锁定销售、Toast 后返回列表 | 冲突时提示重新加载 | 是 |
| 查看账单 | `settlement-confirmed-list` | 具有批次读取权 | `GET /batches/:batchId/settlements/:settlementId` | 显示不可编辑详情 | 404/无权提示并返回 | 否 |

- 请求上下文：路径中的 `batchId` 决定工作区和批次；服务端从登录身份判权，客户端不传工作区或成员权限。
- 确认请求：`saleIds`、`expenseIds`、`costShares[{userId,amount}]`、`profitShares[{userId,percentage}]`；金额为最多一位小数的非负字符串，比例为 0–100 且最多两位小数的数字。服务端将比例转换为百分之一权重后计算，避免浮点比例求和误差。
- 计算：销售额与成本来自确认时的选中销售；费用来自确认时有效费用。利润 = 销售额 − 费用 − 成本。每人的应收应付为“利润份额 − 实收销售款 + 实付采购款 + 实付费用”；正数为应收、负数为应付。采购实际付款按选中销售成本在对应商品全部采购成本中的比例分摊并写入快照；成本承担作为成本返还快照和成本建议依据，不替代实际付款记录。转账建议以债务人与债权人贪心匹配，金额全部使用十分之一元整数，尽量减少笔数。
- 费用边界：已选销售关联的未撤销费用由服务端强制纳入；未关联费用仅在请求包含时纳入；费用不得重复纳入已确认账单。
- 错误码：`FORBIDDEN`、`NOT_FOUND`、`NO_SETTLABLE_SALES`、`INVALID_SETTLEMENT`、`SETTLEMENT_CONFLICT`、`BATCH_CLOSED`；前端展示返回的中文 `message`，冲突提示重新加载。
- 前端显隐不替代服务端授权；确认接口再次验证角色、批次开放状态、销售/费用状态和全部合计。

## 风险、备份与回滚

- 数据准确性：所有金额使用十分之一元整数计算并将结果快照化；利润比例使用百分之一权重并以 `numeric(5,2)` 快照保存；确认前后均由服务端校验，事务和唯一索引阻止并发重复结算。
- 权限：只有批次 owner 或工作区 owner/admin 能预览和确认；普通批次成员只能读取确认账单。
- 不可变锁定：已确认销售和纳入费用不能直接修改或撤销；本次不提供撤销，错误留待后续调整记录处理。
- 迁移：仅新增表，不修改或删除既有数据；本地迁移失败可停止应用并回滚部署版本，已确认账单数据不手工删除。
- 残留精度风险：采购付款按商品采购成本比例分摊到本次消耗成本，存在十分之一元的可见舍入；最后一位分配给稳定排序中的最后成员并写入快照。

## 验收标准

- 管理者能结算一笔、多笔或当前全部未结账销售；已关联费用自动纳入。
- 成本承担合计不等于商品成本、利润比例不等于 100% 或超过两位小数时不能进入预览/确认。
- 确认后销售不再出现在草稿中，销售和纳入费用不可撤销；账单详情显示锁定快照与建议。
- 只读成员能查看已确认账单但不能创建或确认。
- 后端 typecheck/test、前端 typecheck/build 通过；在 390×844 和 430×932 完成主流程、截图和 `data-ai-id` 扫描。
