# B4 协作台账与结算：测试与验收计划

## 结论

本次重点证明：阶段账单只结算有效且未锁定的销售；确认时的成本、利润、应收应付和转账建议可复算；权限与不可重复结算在服务端生效；移动端流程与已确认原型一致。

## 验收场景

| 类别 | 场景 | 预期结果 |
|---|---|---|
| 成功 | 勾选两笔未结账销售并确认 | 仅两笔销售及其关联费用被锁定，生成账单 |
| 成功 | 在销售选择页全选 | 仅当前所有未结账销售被选中，不关闭批次 |
| 成功 | A 承担全部成本、A/B 利润各 50% | 成本返还归 A，利润按 50/50 计算，结果可解释 |
| 边界 | 商品成本为 0 | 仍允许填写并确认利润比例 |
| 边界 | 本次利润为负 | 按比例分摊亏损，预览明确显示“亏损” |
| 校验 | 未选销售 | 下一步提示至少选择一笔销售 |
| 校验 | 成本承担合计不等于成本 | 服务端拒绝确认并返回中文提示 |
| 校验 | 利润比例超过两位小数、负数或合计不为 100 | 前端限制输入；服务端拒绝非法请求 |
| 精度 | A 33.33%、B 66.67% | 比例合计为 100%，预览和确认快照保留两位小数，利润按百分之一权重计算 |
| 冲突 | 两次确认同一笔销售 | 仅首个事务成功，后一个返回冲突且不写入重复账单 |
| 锁定 | 确认后再次创建账单 | 已确认销售不在草稿列表；纳入费用不可再次纳入 |
| 锁定 | 尝试撤销已结算销售或费用 | 拒绝并保留原记录 |
| 权限 | viewer 或 editor 请求预览/确认 | 返回 403；已确认账单仍可读取 |
| 页面 | 无未结账销售 | 显示“暂无未结账销售”，仍可看已确认账单 |

## 自动化验证

- 在 `apps/backend` 运行 `npm run typecheck`、`npm test`，覆盖结算计算辅助函数、接口注册和既有回归。
- 在 `apps/backend` 运行 `npm run db:check`，确认迁移元数据可通过静态检查。
- 在 `apps/web` 运行 `npm run typecheck`、`npm run build`。
- 对确认事务使用数据库唯一约束和 `FOR UPDATE` 锁作为并发防护；本地未配置集成数据库时记录为人工/部署前专项验证项。

## 人工验收

1. 以批次 owner 身份进入批次详情的“结算”，确认首页的未结账数量、开始结算入口和已确认账单列表。
2. 在 390×844 下选择部分销售，确认关联费用自动纳入；检查全选、清空和“至少选择一笔销售”提示。
3. 输入成本承担与利润比例，验证可填写 `33.33` 等两位小数，确认利润比例合计不为 100% 时停留在第二步；确认预览的销售额、费用、成本、利润、应收应付和分行转账建议。
4. 点击“确认账单”，检查二次确认文案、成功 Toast、列表更新，以及再次创建时已确认销售不再出现。
5. 打开账单详情，确认所有数据只读且与预览一致。
6. 在 390×844 与 430×932 截图，对照 `prototype/index.html` 检查单列、底部操作、无横向溢出和遮挡。
7. 扫描实现中的 `data-ai-id`，与 `data-ai-id-registry.md` 对照，确认注册 ID 无遗漏且列表项使用稳定 UUID。
