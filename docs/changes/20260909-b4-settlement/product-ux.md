# 产品与 UX 定义：B4 协作台账与结算

## 结论与确认

B4 以“阶段账单”为核心：用户从当前批次的未结账销售中选择一笔、多笔或全部，确认本次商品成本由谁承担，并在计算时填写利润分配比例后，系统生成利润、应收应付和转账建议。成本承担用于确定成本由谁承担；扣除成本和费用后的利润按本次填写的利润比例分配。卖出人只表示谁先收到销售款，不改变利润归属。

“全选”位于创建账单的销售选择页，勾选当前所有未结账销售，不关闭批次，也不包含未来销售；有新的销售后仍可再次创建阶段账单。产品规则已确认，原型位于 `prototype/index.html`，待确认页面结构和交互后进入技术设计。

## 用户、问题与范围

- 目标用户/角色：批次 owner；工作区 owner/admin 在现有权限规则下可管理批次结算。其他有批次读取权的成员可查看已确认账单，不能创建或确认。
- 使用场景与触发入口：共同出售小卡后，成员希望先结算已经卖出的部分，而不用等待全部库存卖完。
- 当前问题：销售、收款人、费用和采购成本已经记录，但不知道本次利润如何分、谁该收钱、谁该付钱。
- 产品目标：让用户像选择滴滴开发票订单一样选择销售记录，生成一张可解释、不可重复计算的阶段账单。
- 用户完成任务后的可观察结果：已确认账单显示本次利润和转账建议；被选销售不再出现在下一次待结算列表中。
- 本次做什么：销售选择、费用纳入、成本承担确认、利润比例填写、账单预览与确认、已确认账单列表和详情。
- 本次不做什么：支付或转账；自动从平台同步订单；最终批次关闭；撤销已确认账单；长期固定的利润分配设置；报表或导出。

## 用户流程、规则与场景

### 用户主流程

~~~text
批次详情 → 结算
  └─ 开始结算 → 勾选一笔、多笔或全选全部未结账销售
       → 确认纳入费用 → 确认成本承担与利润比例 → 预览账单 → 确认
       → 锁定账单，所选销售闭环
~~~

### 业务规则与权限

- 一张阶段账单至少选择一笔未撤销、未结账的销售。用户可逐笔勾选，也可使用销售选择页的“全选”。
- “全选”仅代表创建时当前的所有未结账销售；不会关闭批次，未卖库存和以后新增销售不受影响。
- 与已选销售关联的费用默认纳入；未关联销售的批次费用由用户自行选择是否纳入。撤销的费用不能纳入。
- 系统根据已选销售数量计算对应商品成本，并按采购记录的成本承担方式提供建议。
- 用户必须确认每位批次参与人的成本承担金额，可修改；本次确认金额总和必须等于本次商品成本。
- 本次利润 = 本次销售额 − 纳入费用 − 本次商品成本。成本承担用于返还本次成本；每人的利润份额 = 本次利润 × 本次确认的利润比例。
- 利润比例在创建账单时填写，不在批次中预先设置。默认由本次参与结算的成员平均分配；可修改为 0–100 且最多两位小数的百分比，所有成员比例合计必须正好为 100%。输入框只接受数字和一个小数点，不接受负数或其他字符。
- 成本为 0 时，仍可确认利润比例；若本次利润为负数，系统按同一比例分摊亏损，并在预览中明确标注“亏损”。
- 系统结合每人实际收到的销售款、实际支付的采购款、实际支付的费用和利润份额，生成“应收 / 应付”及尽量少的转账建议。成本承担决定利润比例，不替代实际付款记录。
- 确认账单后，账单、所选销售、纳入费用和本次确认成本均锁定；所选销售不能再直接修改、撤销或重复结算。账单错误留待后续“调整记录”能力处理。
- 最终批次结果只汇总所有已确认阶段账单；未结账销售不会进入结果。

### 需求场景

#### Requirement: 全部或部分销售均可结算

系统 SHALL 允许用户结算当前批次全部未结账销售，或只勾选其中部分销售。

#### Scenario: 全选当前全部销售

- **WHEN** 用户在销售选择页选择“全选”
- **THEN** 系统勾选当前全部未结账销售，并允许用户继续确认费用、成本和账单

#### Scenario: 结算部分小卡销售

- **WHEN** 用户勾选两笔未结账销售而未勾选其他销售
- **THEN** 账单只计算这两笔销售及其纳入费用，未勾选销售仍可在下次结算时选择

#### Requirement: 利润按本次确认比例分配

系统 SHALL 在每次创建账单时，让用户确认利润分配比例，并按该比例分配扣除成本和费用后的利润。

#### Scenario: A 承担全部成本，利润平分

- **WHEN** A 最终承担本次全部 130 元成本，A、B 在本次账单填写利润比例各 50%
- **THEN** 先将 130 元成本计入 A 的成本返还，再将扣除成本和费用后的利润按 A 50%、B 50% 分配，即使销售款由其中一人先收取

#### Scenario: 提交时利润比例不是 100%

- **WHEN** 用户填写 A 60%、B 30%后点击下一步
- **THEN** 系统提示利润比例合计必须为 100%，并停留在当前页面

#### Requirement: 已确认销售不可重复结账

系统 SHALL 在账单确认后锁定所选销售，使其不能再次进入待结算列表。

#### Scenario: 再次创建账单

- **WHEN** 用户确认一张包含两笔销售的账单后再次进入结算
- **THEN** 这两笔销售不再显示为可选项，只显示仍未结账的销售

## 页面与交互规格

### 页面地图

~~~text
批次详情
  └─ 结算
      ├─ 已确认账单列表
      └─ 开始结算 → 创建账单
          ├─ 选择销售与费用
          ├─ 确认成本与利润比例
          └─ 预览并确认账单
~~~

### 页面：结算首页

- 核心任务：查看已确认账单，开始创建一张新账单。
- 信息层级：待结算销售数量 → 开始结算入口 → 已确认账单列表。
- 主操作：开始结算。
- 空状态：没有可结算销售时说明“暂无未结账销售”；已确认账单仍可查看。

#### 线框

~~~text
结算
当前有 5 笔销售可结算
[开始结算]

已确认账单
9 月 9 日 · 2 笔销售 · 利润 ¥xx.x    >
~~~

### 页面：创建账单

- 核心任务：选择本次销售和费用，确认成本承担，理解结果后确认。
- 信息层级：步骤提示 → 当前步骤内容 → 固定底部“下一步 / 确认账单”。
- 第一步“选择销售”：每笔销售展示商品、数量、成交时间、卖出人、成交金额；支持全选、清空和逐笔勾选。
- 第一步“选择费用”：已选销售关联费用默认勾选且标记“已关联”；未关联费用可自行勾选。
- 第二步“确认成本与利润比例”：展示商品成本合计及每位参与人的成本承担金额输入；同时展示利润比例输入，默认平均分配。
- 利润比例输入框只接受 0–100 且最多两位小数。用户点击下一步时校验合计是否为 100%；不通过时在当前操作处提示并停留在本页，不常驻展示规则说明。
- 第三步“账单预览”：展示销售额、费用、成本、利润；每人展示成本承担、成本返还、收到销售款、垫付费用、利润比例、利润份额、应收/应付；转账建议按付款人、收款人和金额分行展示。
- 危险操作与确认：最终“确认账单”前说明所选销售会锁定、不可再次结账；使用二次确认。

#### 线框

~~~text
创建账单                                1 选择 → 2 成本和利润 → 3 预览

本次销售                         [全选] [清空]
☑ 小卡 A · 1 张 · 2026-09-09 12:00:00 · A 收款 ¥100.0
☐ 小卡 B · 1 张 · 2026-09-09 13:00:00 · B 收款 ¥120.0

本次费用
☑ 邮费 ¥10.0 · A 支付 · 已关联小卡 A

                                              [下一步]
~~~

### 页面：账单详情

- 核心任务：查看已锁定账单及实际应收应付。
- 信息层级：账单状态与确认时间 → 汇总金额 → 参与人结果 → 转账建议 → 纳入销售与费用。
- 只读：所有字段和明细均不可在页面直接修改。

## 状态、响应式与验收

| 状态 | 页面表现 | 可执行操作 |
|---|---|---|
| Loading | 保留标题与步骤骨架 | 禁用选择与确认 |
| Empty | 暂无未结账销售说明 | 查看已确认账单、返回 |
| Error | 加载失败和重试 | 重试、返回 |
| 无权限 | 只读账单说明 | 查看有权账单 |
| Disabled | 确认中时禁用下一步/确认 | 等待或取消 |
| Success | 账单确认 Toast，返回已确认账单列表 | 查看账单或创建下一张 |

- 移动端：390×844 与 430×932 单列展示；选择销售使用清晰列表和勾选框，金额信息不横向溢出；底部操作固定且不遮挡内容。
- 复用：`MobileShell.vue`、批次详情页、Vant Cell、Checkbox、Field、Dialog、Toast、Tag。
- 视觉方向：金额和“应收/应付”用清楚文字搭配颜色；不使用复杂图表或卡片墙；确认账单为唯一主操作。
- 页面验收：用户能从“开始结算”进入销售选择页，并能选择部分或全选全部销售；能看懂利润、应收应付和转账建议；锁定影响和不可选销售有明确说明。
