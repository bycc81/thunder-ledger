# 快速售出测试与验收计划

## 结论

验收要证明：快速售出可独立录入且不强制拆分成交价；关联库存数量和库存账成本准确；快速售出与普通销售在费用、结算和报表使用同一经济口径。还必须证明普通销售、采购、库存调整和既有结算没有回归。

## 验收场景

| 编号 | Requirement | Scenario | 预期结果 |
| --- | --- | --- | --- |
| S1 | R1 关联库存 | 一行关联专辑 1 件、小卡 1 件 | 两个库存分别减少 1，库存账成本按时间线重放 |
| S2 | R1 关联库存 | 两个商品行关联同一库存，合计等于可用量 | 保存成功，合计数量正确 |
| S3 | R1 关联库存 | 发生时间库存不足或并发保存后超量 | 409 `INSUFFICIENT_INVENTORY_AT_TIME`，整笔事务回滚 |
| S4 | R2 自由商品 | 未建商品、未关联库存，填写名称/数量/成本 | 保存成功；不新增商品、上架或采购库存；本单成本可结算 |
| S5 | R2 成本输入 | 有关联库存后输入自定义成本 | 详情本单成本等于输入，库存账成本按账本值；可不同 |
| S6 | R2 成本快捷操作 | 关联开关未开、未选择关联数据或关联数无效 | 按库存成本禁用；三条件满足后启用，填入关联成本×售出数量 |
| S7 | R2 数量确认 | 售出 2 件、仅关联 1 件库存 | 保存前二次确认；取消不提交，确认按原值保存；系统不改数量 |
| S8 | R2 表单删除 | 删除商品行或关联库存项 | 图标按钮和二次确认；取消不删，确认才删 |
| S9 | R3 撤销 | 未结账且有关联库存的快速售出撤销 | 要求原因和确认；撤销记录写入，库存恢复 |
| S10 | R3 撤销 | 已纳入账单的快速售出撤销 | 409 `QUICK_SALE_SETTLED`，无数据变化 |
| S11 | R4 费用 | 费用关联快速售出 | 费用与快速售出详情互见；结算该单时费用强制纳入 |
| S12 | R4 费用 | 同时提交 `saleId` 与 `quickSaleId` | 400 `INVALID_EXPENSE` |
| S13 | R5 结算 | 选择一笔普通销售和一笔快速售出预览、确认 | 同一候选列表、同一利润比例和成员计算；分别写快照 |
| S14 | R5 结算 | 再次结算已结账快速售出 | 校验失败，不重复生成快照 |
| S15 | R5 分摊 | 关联库存由不同成员付款/承担，且本单成本不同于库存账成本 | 结算成本等于本单成本；按库存权重分摊，分取整守恒 |
| S16 | R6 报表 | 快速售出后查看销售、利润、成员、待结算 | 销售额、手续费、本单成本、卖出人、数量和来源均计入；未关联库存不变库存统计 |
| S17 | R7 回归 | 普通销售、采购更正、库存调整、既有费用和账单 | 既有测试全绿，普通销售结果不变 |
| S18 | R8 权限 | viewer 打开页面；editor/owner 保存；关闭批次写入 | viewer 只读；editor/owner 可写；关闭批次 409 |
| S19 | R8 隔离 | 关联其他工作区/批次商品、成员或单据 ID | 400/404，不泄露外部数据 |

- 关联库存数量、`consumed_cost_cents`、库存账分摊和快速售出本单成本均守恒。
- 事务失败时没有快速售出单、商品行、关联项、撤销或半更新账本。
- 普通销售 `sale_cost_allocations` 和既有结算测试结果不变。

## 人工验收

在 390×844 或同等移动端视口执行并留存截图：

1. 打开快速售出表单，检查加载、空、错误、无权限和保存成功状态。
2. 新增两行商品；一行关联多个库存，确认计数器范围为 1..当前可用量，删除图标不挤压名称。
3. 确认按库存成本在“开关联开关 + 选择关联库存 + 数量至少 1”前置灰；启用后带入预期金额，手工修改后不自动覆盖。
4. 故意让售出数量和关联数量不一致：取消确认后留在表单；确认后成功保存，所有填写值不变。
5. 打开详情，确认本单成本、库存账成本、来源标识、关联费用和结算状态。
6. 检查交易列表、费用关联选择和结算草稿：普通销售与快速售出并列，仅来源 tag 不同，勾选和预览一致。
7. 检查删除、移除、撤销都出现 Vant 二次确认；撤销要求原因，已结账单不可撤销。
8. 检查按钮规格：行内 36px、次级 40px、保存/确认/危险 44px；没有横向溢出、遮挡或拥挤。
9. 对照 [data-ai-id-registry.md](data-ai-id-registry.md) 扫描实现，确认根节点、弹层、列表项和危险操作都有稳定 ID，且不含用户输入。

## 结果与残留风险

初版计划完成时尚未实现；当前实现与已执行的冒烟结果见下方“冒烟实测记录”。

残留风险：本单成本可与库存账成本不同，这是已确认规则。实现必须在详情和结算中明确展示本单成本，避免把库存账成本误作结算口径。生产迁移、镜像构建和发布尚未授权；执行前需备份数据库、报告验证结果并等待用户明确确认。

## 冒烟实测记录（2026-09-29，浏览器 E2E）

修复：`apps/web/src/main.ts` 全局注册遗漏的 `Stepper`、`Switch` 与 `CheckboxGroup`；`QuickSaleFormPage.vue` 的库存勾选框停止事件冒泡，避免点击勾选框后被所在行重复切换。仅调整前端组件注册和交互，不影响后端库存、成本或结算计算。

- 场景 1：两件关联库存的快售。数量可由 1 调至 2，开启关联库存后可选择库存并自动填写成本；保存成功，关联库存可用量由 4 降至 2，库存总成本由 700.00 变为 350.00。
- 场景 2：两件商品不关联库存。两行商品可正常保存，库存数量不变。
- 场景 3：关联库存多选。在 390×844 移动端视口下直接勾选库存 A、库存 B 后，两项同时保持选中；点击库存 A 的整行后仅取消 A，库存 B 保持选中。确认后正确生成保留项的关联库存行。
- 守卫：售出 2 件但只关联 1 件库存时，保存前会出现二次确认；全程无 console 错误。

## 普通销售可售库存回归（2026-09-29）

- 问题：普通销售表单的商品接口漏扣快速售出关联库存，导致表单可售数量高于库存总览。
- 验收：对同一批次分别读取库存总览和普通销售商品列表，“专辑”均为 9 件，“卡”均为 1 件；在 390×844 普通销售表单选择“专辑”后显示“当前可卖：9 件”。
- 边界：仅扣除未撤销快速售出的 `quick_sale_inventory_consumptions`；未关联库存的快速售出不改变普通销售可售数量。

## 普通销售数量控件回归（2026-09-29）

- 目标：普通销售数量使用与快速售出一致的步进器，同时支持加减和直接输入。
- 验收：未选择商品时控件禁用；选择可卖 9 件的“专辑”后，点击加号可从 1 变为 2；直接输入 99 后自动限制为 9；最小值为 1。
- 范围：仅前端输入约束，不修改后端库存扣减、成本和结算计算；后端库存校验继续作为最终保护。

## 快速售出页面展示回归（2026-09-29）

- 交易列表的商品名称限制为最多两行，超出部分省略，避免长名称挤压状态与来源标签。
- 快速售出详情摘要移除了重复的“· x 件”；“待结账”和“快速售出”标签保留 8px 间距，来源标签继续使用与交易列表相同的主色描边 Tag。
- 详情接口未提供汇总名称时，摘要标题回退为商品项名称的“+”组合，避免标题留白。
- 快速售出表单统一使用“商品项”文案；关联库存开启后，右侧以文字按钮提供“添加关联库存”，不再显示“尚未选择关联库存”占位文案。
- “添加关联库存”仅保留蓝色文字和透明点击区域，不使用填充色或边框，触控区域仍保持 44px。
- 范围：仅前端展示和交互布局；不修改库存、成本、手续费或结算计算逻辑。

## 商品明细紧凑布局（2026-09-29）

- 快速售出详情的商品明细改为双列：左侧显示商品名称与关联库存，右侧显示数量与本单成本。
- 长商品名称最多两行，右侧摘要固定宽度，减少留白且不改变详情接口、库存、成本或结算逻辑。

## 零成本采购与快速售出结算入口回归（2026-09-29）

- 商品组采购总成本、各款式成本和成本承担均为 `0.00` 时可保存，所有成本承担记录为 0，不产生 NaN 或数据库金额错误。
- 仅有未结账快速售出时，结算首页显示待结算数量并提供“开始结算”入口；确认后的纯快速售出账单出现在账单列表，交易数量正确。

## 快速售出本单成本输入回归（2026-09-29）

- 本单成本为必填字段：空值在前端保存前提示，不会被静默替换为 `0`；输入 `0` 或 `0.00` 合法并原样提交。
- 已移除“默认 0”占位文案，避免误导用户跳过必填输入。
- “售出数量”和“关联库存”行标签统一为 14px，与“本单成本”字段标签一致；“添加关联库存”维持无边框、无填充的轻量文字按钮，触控高度仍为 44px。

## 销售来源标签一致性回归（2026-09-29）

- 交易列表的普通销售和快速售出都在右上角显示同级来源标签，分别为“普通销售”“快速售出”；标签均使用主色描边样式，结账状态或撤销操作继续在其下方显示。
