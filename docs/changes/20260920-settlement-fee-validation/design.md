# 结算手续费实库验证：设计记录

## 结论

在本地 Docker PostgreSQL 中创建带 `fee-validation-20260920` 标识的隔离测试数据，走商品、采购入库、销售和结算预览流程，核对两笔带手续费销售的手续费、净收款、利润与成员应收应付。现有“张元英小卡”数据只读核对，不创建或确认其账单。

## 风险等级

`L2`。验证会写入本地业务数据，且测试账单确认后会锁定测试销售；不连接生产环境，不删除或修改既有业务数据。

## 背景与目标

确认平台手续费是否同时正确影响账单汇总净收款、利润和卖出人实收款，排查“张元英小卡”三笔销售中两笔含手续费时的疑问。

## 非目标

- 不调整收益或结算规则。
- 不确认或修改既有“张元英小卡”销售。
- 不发布、迁移或删除本地数据。

## 验证数据与流程

- 测试批次、商品和销售记录统一使用 `fee-validation-20260920` 标识。
- 新建商品，采购入库 3 件，成本合计 ¥90.00。
- 创建 3 笔各 1 件销售：¥100.00（手续费 ¥10.00）、¥200.00（手续费 ¥5.00）、¥500.00（无手续费）。
- 预期：销售额 ¥800.00；手续费 ¥15.00；净收款 ¥785.00；商品成本 ¥90.00；费用 ¥0.00；利润 ¥695.00。
- 结算预览与账单确认均由 API 服务端计算；只在测试数据上确认账单。

## 风险、备份与回滚

- 影响：新增本地测试工作区/批次/商品/采购/销售/账单记录。
- 隔离：名称标识使记录可辨识；不使用现有批次或销售。
- 回滚：不执行删除以避免破坏审计/账单快照；测试记录保留供复核。

## 验收标准

- 现有“张元英小卡”三笔销售的手续费总额、销售额和结算预览可被读取并手算复核。
- 隔离样本的服务端预览与确认账单均符合预期金额。
- `salesReceived` 按成交额减手续费归集到卖出人，成员应收应付合计为零。

- “日咖一回目 / 张元英小卡”当前有 3 笔未结算销售：¥500、¥200、¥100，三笔 `service_fee_cents` 均为 `0`，因此其待结算销售额和净收款均为 ¥800。
