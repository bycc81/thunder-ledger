# B5 测试与验收计划

## 结论

B5 必须证明报表只读、口径准确、权限不越界、导出结果与页面筛选一致、审计查询不泄露敏感信息，并证明备份可用且恢复演练不会连接生产写入。

## 验收场景

- 报表：
  - 有库存、销售、费用和已确认结算数据时，库存、销售、利润、成员贡献和待结算结果与明细一致。
  - 个人批次和协作批次数据不混淆。
  - 已确认账单保持不可变，报表能区分已结算和待结算数据。
  - 空批次、空日期范围、无数据范围显示空状态。
  - 非法日期范围、非法批次和不存在的报表类型被拒绝。
- 权限：
  - 用户不能查询或导出不属于自己工作区/批次的数据。
  - 查看者只能读取允许范围，不能查看工作区审计。
  - owner/admin 能查看当前工作区审计，不能通过参数访问其他工作区。
  - 系统管理员不会因为全局账号权限绕过工作区业务隔离。
- CSV：
  - 导出字段与当前报表类型匹配，金额和时间格式稳定。
  - 销售报表“发生时间”按上海时区输出为 `YYYY-MM-DD HH:mm:ss`。
  - 导出结果与页面筛选条件一致。
  - 导出成功和失败都写入审计，失败不生成伪造下载。
  - CSV 不包含密码、Token、连接串或不必要的完整隐私字段。
- 审计：
  - 查询动作、操作者和时间范围生效。
  - 审计记录按时间倒序，分页/限量行为明确。
  - 审计查询失败显示错误，不显示为空。
- 备份恢复：
  - 备份文件可被校验，来源和时间可追溯。
  - 在隔离数据库恢复后，核心表数量、迁移版本和关键账务汇总可核对。
  - 恢复演练不使用生产写连接，不覆盖生产数据。
  - 演练失败时发布门禁阻断，并保留回滚和修复记录。

## 自动化验证

- 后端：`npm run typecheck`、`npm test`
- 前端：`npm run typecheck`、`npm run build`
- 数据库：`npm run db:check`；若新增迁移，再做受控迁移验证
- 容器/部署：`docker compose config`、`docker compose build`、`/api/healthz`、`/api/readyz`
- API 集成测试覆盖报表口径、权限、CSV 响应和审计记录。

## 人工验收

1. 用 owner/admin/editor/viewer 分别登录，验证报表入口、批次范围和操作记录入口。
2. 在 390×844 和 430×932 视口检查筛选、汇总、列表、弹窗无横向溢出和遮挡。
3. 选择不同报表类型和日期范围，验证 loading、empty、error、permission、disabled、success 状态。
4. 销售报表核对四项汇总：销售额、销售成本、销售利润（未扣费用）、销售数量。
5. 导出 CSV，核对筛选范围、字段、金额、`YYYY-MM-DD HH:mm:ss` 发生时间和审计记录。
6. 使用隔离数据库执行备份恢复演练，核对迁移版本和 B4 账单/调整单结果。
