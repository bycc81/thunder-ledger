# 批次与工作区软删除测试计划

## 结论

验证软删除不清理业务数据、权限边界保持有效，并确保工作区可在仍有批次时直接隐藏。

## 验收场景

- 批次所有者删除有业务记录的批次，批次从列表隐藏。
- 工作区管理员可删除任意批次；编辑者、查看者收到 403。
- 工作区创建人可删除仍有未删除批次的工作区；批次记录保持未删除，但随工作区从界面隐藏。
- 批次详情接口返回当前用户的批次角色，详情页据此显示危险操作区。
- 两个删除弹窗均需二次确认，并展示记录保留、无法继续操作的后果。

## 自动化验证

- 后端：`npm run typecheck`、`npm test`、`npm run test:roles`。
- 前端：`npm run typecheck`、`npm run build`。

## 人工验收

1. 创建或选择含业务记录的批次，以批次所有者在批次列表点击右上角 `···` → 删除，确认提示与删除结果。
2. 打开同一批次详情，确认底部“危险操作”中也能删除，且保留二次确认。
3. 选择仍有批次的工作区，以创建人进入工作区管理，确认“删除工作区”按钮可用；点击后检查二次确认文案和隐藏结果。

## 残留风险

- 删除后没有恢复入口；维护者需确认目标 ID 后手工执行设计记录中的 `deleted_at = NULL` SQL。
- 本轮不会物理删除历史记录，数据库存储不会因软删除立即减少。
