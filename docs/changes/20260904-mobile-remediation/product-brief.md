# 产品定义：移动端黄金页面整改

## 结论

本变更先建立可验收的“工作区概览”黄金页面，作为后续批次、成员、操作记录和我的页面的移动端基线。页面先于接口契约，原型确认后才进入 Vue 实现；现有 API 仅作为已存在的领域能力进行核对，不新增后端能力。

## 用户与场景

- 目标用户/角色：工作区所有者、管理员、编辑者、查看者。
- 使用场景与触发入口：登录后进入当前工作区，快速确认状态、切换工作区并进入批次或成员任务。
- 当前问题：现有实现虽可运行，但页面结构、视觉密度和交互路径偏离原型，无法作为移动端工作台使用。

## 目标与范围

- 产品目标：用户在 390px 级别屏幕上能立即理解当前工作区，并从一个页面进入最常用任务。
- 可观察结果：工作区上下文明确；成员、批次、操作记录数量可读；最近批次可打开；快捷操作可进入对应模块；工作区切换不混淆数据范围。
- 本次做什么：完成工作区概览产品定义、UX 规格、HTML 原型、页面/API/权限契约和 `data-ai-id` 注册表。
- 本次不做什么：不改后端数据库和 API；不重做其他页面；不在原型确认前改 Vue 页面。

## 用户主流程

```text
登录 → 当前工作区概览 → 查看最近批次/切换工作区/进入成员或操作记录
                         └→ 新建批次
```

## 页面清单

| 页面 | 用户主任务 | 进入方式 | 离开/下一步 | 关键状态 |
|---|---|---|---|---|
| 工作区概览 | 查看当前空间状态并进入常用任务 | 登录成功、底部导航 | 批次详情、批次列表、成员、操作记录、工作区切换 | 加载、空批次、错误、无权限 |
| 工作区切换 | 选择数据上下文 | 顶部工作区按钮 | 返回概览并刷新范围数据 | 当前选中、空工作区 |
| 新建批次 | 创建一个批次 | 概览主操作或快捷操作 | 创建成功后进入批次列表 | 校验、提交中、失败 |

## 业务规则与权限

- 所有统计、最近批次和操作入口只属于当前工作区。
- 所有者和管理员可创建批次；编辑者和查看者不可创建。
- 工作区切换后必须刷新批次、成员和操作记录事实源。
- 前端显隐不替代 API 授权。

## 需求场景

### Requirement: 当前工作区上下文必须始终可见

#### Scenario:

- **WHEN** 用户进入概览
- **THEN** 顶部显示当前工作区名称和切换入口，主标题与之保持一致

### Requirement: 概览必须提供可执行的下一步

#### Scenario:

- **WHEN** 用户查看最近批次或快捷操作
- **THEN** 每个入口都能进入对应任务，不能只有统计展示

### Requirement: 页面契约先于实现

#### Scenario:

- **WHEN** 原型、字段、权限和状态尚未确认
- **THEN** 不得开始 Vue 页面或新增 API 实现
