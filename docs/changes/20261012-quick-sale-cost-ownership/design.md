# 快速售出无库存成本归属修复

## 结论与风险等级

L2：涉及成本付款、承担与结算数据准确性。未关联库存的商品行必须显式选择付款人及成本承担成员，金额合计等于该行本单成本；沿用采购表单的规则和既有结算算法。已有记录保留原归属。本轮仅完成代码和受控验证，生产迁移与发布另行确认。

## 产品与 UX 输入

现有表单内补齐缺失字段，不新增页面或改变保存主流程，属于已有页面字段修复，不触发完整原型阶段。未关联库存时显示付款人与承担编辑区；已关联库存时显示“付款及成本承担沿用关联库存”。关联开关已打开但未选择库存时仍按未关联处理。切换关联保留手动草稿，提交只携带当前生效数据。

## 背景与当前缺口

`apps/backend/src/quick-sales.ts` 在商品行没有库存来源时，把 payer 与 burden 都归属 sellerUserId。表单没有承担字段，用户无法指定实际垫付款人或分摊人；混合单据的未关联行也存在同样问题。采购更正会重建快速售出分配，因此手动归属必须按商品行持久化。

## 页面/API 契约

- 创建快速售出接口：`POST /api/batches/:batchId/quick-sales`。无库存商品行增加必填 `payerUserId` 和 `costShares: [{ userId, amount }]`；金额为最多两位小数的非负字符串，与现有采购一致。成本为零仍须选择人员并提交合计为零的承担金额。
- 服务端拒绝缺失、重复成员、非法金额、承担总额不符、非当前批次人员；关联库存行拒绝手动字段。保持既有批次写权限和关闭批次校验。
- 单据事务内保存每行 payer/burden 原始分配，重建汇总时保留手动分配，关联行继续按库存来源权重计算。新单据无库存不再隐式回退卖出人。
- 详情接口：`GET /api/batches/:batchId/quick-sales/:quickSaleId`。每行增加 `costAllocationSource`（manual / inventory / legacy_seller）与 `costAllocations`（allocationType、userId、username、amount）。显示无库存的付款/承担人和金额；旧记录无手动行时明确标记历史默认归属卖出人。
- 无关联库存时按钮显示“保存快速售出”，有库存时沿用“保存并扣减库存”。加载、错误、保存中和失败反馈沿用原页面。
- 稳定定位 ID 见 `data-ai-id-registry.md`，保留所有已有 ID。现有权限、列表排序和路由不变。

## 数据与影响范围

新增可重复迁移 `apps/backend/migrations/024_quick_sale_item_cost_allocations.sql`，表 `quick_sale_item_cost_allocations` 保存商品行手动成本来源，主键为商品行、类型、成员；外键指向商品行与用户，金额非负。只存新单据明确填写的归属，不回填历史记录。更新快速售出 API、创建/详情页、API 类型和用户手册；不调整结算公式、利润比例、库存消耗口径或权限模型。

## 风险、备份与回滚

金额使用整数分计算与校验，付款和承担分别保存。手动分配在采购更正重建中保留，混合单据仅库存行随库存来源变化。服务端拒绝跨批次人员；审计沿用既有创建记录，不增加备注或凭据日志。不修改旧单据或锁定账单。

回滚应用时保留新增表及手动分配数据；存在新记录时不能回退到会忽略手动归属的旧代码，优先前向修复。生产前需备份并按部署规范执行迁移、构建及健康检查，须获用户确认；本轮不部署。

## 验收标准

1. 无库存行必须选择付款人与至少一名承担人，支持添加、删除、均摊；承担合计等于本单成本，包括 0.00。
2. 卖出人、付款人、承担人可不同；结算预览的付款额和承担额分别正确，合计守恒。
3. 服务端拒绝缺失字段、重复/跨批次成员、错误合计、非法金额和关联行混入手动字段。
4. 混合单据分别应用手动分配和库存来源；采购更正重建不得覆盖手动分配。
5. 历史无库存记录仍归属原卖出人，详情明确标注；撤销与已结账限制维持既有行为。
6. 目标移动视口完成截图、关键交互、稳定 ID 与横向溢出检查，后端和前端最低检查通过。
