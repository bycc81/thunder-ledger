# 列表时间倒序与销售类型过滤

- 日期：2026-10-10；风险：L1（已有页面与查询展示排序）。
- 用户已确认：普通/快速销售不筛选时混合按卖出时间倒序，增加销售类型过滤；其他审查建议一起修改；保留业务顺序例外。
- 目标：最近业务记录优先，筛选后仍倒序，选择及结算金额不因展示排序变化。

## 页面/API 契约与范围

1. 创建账单「本次销售」：全部/普通销售/快速售出单选过滤，与关键词、收款人多选取交集；普通/快速使用同一展示序列，卖出时间倒序，同时间按创建时间倒序、来源和稳定 ID 排列。
2. 切换过滤不清除已选项；全选/清空只作用于可见记录；普通/快速的提交 ID 数组及关联费用、推荐和预览继续沿用已有契约。
3. 已确认账单交易明细：混合卖出时间倒序，快照无独立创建时间时以来源和稳定 ID 确保顺序。
4. 商品列表及采购商品选择：商品组/独立商品合并按创建时间倒序；保留原详情、采购路由及定位 ID。
5. 工作区切换按创建人首次加入时间倒序（创建时间代理；表无独立创建时间列，缺失创建人记录时置后）；工作区成员与批次参与人按加入时间倒序；批次普通销售商品选项与商品组实际款式按商品创建时间倒序。
6. 库存汇总按最近采购发生时间倒序，再按创建时间和商品 ID 稳定排列。
7. 现有已倒序列表保持当前业务时间口径。图片、模板款式、快速售出单内商品项、结算人员结果、转账明细保留手动或业务顺序；汇总报表原有分组/业务顺序保留。

## 实现边界

无数据库结构、权限、认证、成本/收益算法、结算快照或生产部署变更。修改展示查询排序；结算内部计算与人员分配顺序保持原有契约。
新增销售类型控件使用固定选项、44px 触控目标、可访问单选状态；继续复用 AppMultiSelect 作为人员多选。

## 数据字段核验补充

只读 EXPLAIN 验证发现 workspaces 表没有 created_at（002_batch1_access.sql 中也未定义）。创建工作区的现有流程同时写入创建人的 workspace_members 记录，且创建人不能退出、owner 不能被移除。因此采用创建人加入时间作为工作区创建顺序代理，两种角色列表统一 LEFT JOIN 创建人记录、DESC NULLS LAST、稳定工作区 ID。没有新增迁移，不用当前用户的加入时间替代工作区创建顺序。历史异常记录缺少创建人成员时排在最后，不能还原精确创建时刻。
