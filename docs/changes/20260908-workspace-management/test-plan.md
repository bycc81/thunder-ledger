# 工作区管理测试与验收计划

## 结论

重点验证创建人边界、退出后的访问失效和已有批次的删除保护；构建通过后仍需由用户在移动端页面验收。

## 验收场景

1. 创建人可改名；非创建人请求改名返回拒绝。
2. 创建人管理无批次工作区时可删除；删除后不再出现在列表。
3. 创建人管理曾有批次的工作区时删除按钮禁用，直接请求删除也返回 `WORKSPACE_HAS_BATCHES`。
4. 非创建人成员可退出；退出后 `GET /workspaces` 不含该空间，读取其成员和批次接口被拒绝。
5. 创建人请求退出返回 `WORKSPACE_CREATOR_CANNOT_LEAVE`。
6. 删除或退出后，批次与审计记录仍保留在数据库。
7. 系统管理员不是创建人时不能删除他人工作区。

## 自动化验证

- 后端：`npm run typecheck`、`npm test`。
- 前端：`npm run typecheck`、`npm run build`。
- 静态检查：`git diff --check`。

## 人工验收

1. 在 390×844 和 430×932 打开“工作区管理”。
2. 创建一个没有批次的协作工作区，确认可改名和删除，并确认删除后自动回退。
3. 创建一个批次后返回管理页，确认删除按钮置灰和原因可见。
4. 用被邀请账号进入管理页，确认只能看到退出；退出后刷新并确认空间和批次无法访问。

## 结果与残留风险

- 已通过：后端 `npm run typecheck`、`npm test`；前端 `npm run typecheck`、`npm run build`；开发环境 `/api/healthz` 返回 200。
- 待用户页面验收：创建人改名/删除、成员退出、有批次时禁用删除。
- 残留风险：系统管理员保留既有全局查看权限，退出普通成员关系不会限制该全局权限。
