# v1 四角色与发布准备设计

## 结论

本批次合并完成 owner、admin、editor、viewer 四角色 API 回归，以及生产配置、云端冒烟、发布和回滚检查清单。真实云 Secret 修改、R2 密钥轮换和生产部署不在本批次自动执行，必须在本地证据完成后单独确认。

## 风险等级

`L2`。涉及权限边界、安全配置和生产发布门禁。

## 产品与 UX 输入

本轮不适用。不新增页面，不改变既有用户流程；只验证页面显隐规则与服务端授权一致。

## 背景与目标

会话安全开发与本地验证已经完成。上线前仍需用四类真实数据库用户验证核心读写边界，并把生产配置、云端冒烟、发布和回滚动作整理为可执行检查。

## 非目标

- 不修改 owner/admin/editor/viewer 的既有业务规则。
- 不创建生产账号或写入生产业务数据。
- 不轮换真实云密钥，不执行 Render、Pages、Neon 或 R2 生产变更。
- 不执行 Git 提交、推送或正式发布。

## 当前实现与缺口

- 服务端权限由工作区角色、批次角色和系统管理员标记共同决定。
- 前端通过 `canManageWorkspace`、`canCreateBatch`、`canEditProducts` 和批次角色控制操作入口。
- 当前缺少可重复、隔离的四角色真实 API 回归命令。
- 当前缺少按顺序执行的生产配置、云端冒烟和回滚检查清单。

## 权限矩阵

| 能力 | owner | admin | editor | viewer |
|---|---:|---:|---:|---:|
| 查看工作区、成员、批次 | 允许 | 允许 | 允许 | 允许 |
| 管理工作区成员 | 允许 | 允许 | 拒绝 | 拒绝 |
| 查看操作审计 | 允许 | 允许 | 拒绝 | 拒绝 |
| 创建/编辑商品 | 允许 | 允许 | 允许 | 拒绝 |
| 创建批次 | 允许 | 允许 | 允许 | 拒绝 |
| 管理批次名称/成员/关闭 | 允许 | 允许 | 拒绝 | 拒绝 |
| 查看库存、销售、费用、结算 | 允许 | 允许 | 允许 | 允许 |
| 新增采购、销售、费用 | 允许 | 允许 | 允许 | 拒绝 |
| 创建或确认结算 | 允许 | 允许 | 拒绝 | 拒绝 |
| 查询和导出可访问批次报表 | 允许 | 允许 | 允许 | 允许 |

工作区 editor/viewer 只有加入目标批次后才能访问该批次；owner/admin 自动获得批次管理上下文。

## 方案与影响范围

- 新增独立角色回归程序，使用临时 PostgreSQL、真实用户行、工作区成员和批次成员。
- 使用与正式服务相同的 Fastify 路由和 HttpOnly Cookie JWT 验证，不只测试权限 helper。
- 新增 PowerShell 编排脚本，自动启动临时数据库、执行迁移、运行回归并销毁临时容器。
- 新增发布检查清单，覆盖 Secret、域名、HTTPS、CORS、Cookie、Neon、R2、健康检查、核心闭环和回滚。
- 不改数据库迁移和业务页面。

## 风险、备份与回滚

- 测试数据库名称和容器均带固定测试标识，程序拒绝连接非测试数据库。
- 测试数据只写入临时 PostgreSQL 容器，结束后销毁，不接触现有本地或生产数据库。
- 脚本失败时保留明确错误并在 finally 中停止临时容器。
- 本批次只增加测试和文档；回滚为移除新增脚本、测试入口和记录。

## 验收标准

- 四角色对权限矩阵中的代表性真实 API 得到预期 2xx/403。
- 报表查询和 CSV 导出对四角色均按批次可见范围成功。
- viewer 无法执行商品、采购、销售、费用和成员管理写操作。
- editor 可执行业务编辑，但无法管理成员、审计和结算。
- owner/admin 可管理成员、审计和结算。
- 临时数据库测试不会连接或修改现有数据库。
- 发布检查清单明确区分“已本地验证”和“需生产确认”。

## 开发任务绑定

- 四角色 API 回归：绑定本设计权限矩阵，自动化脚本验证。
- 前端权限契约：静态核对 Pinia 权限计算与关键页面显隐条件，前端 typecheck/build 验证。
- 发布准备：使用 `release-checklist.md` 逐项记录，生产项等待明确确认。
