# v1.0 发布检查清单

## 当前结论

本地上线门禁已完成，当前仍不能正式发布。以下生产配置、云端冒烟、版本记录和部署确认未完成；标记“生产操作”的事项必须在用户明确确认后执行。

## 生产配置

- [ ] Render `DATABASE_URL` 使用 Neon SSL 连接。
- [ ] Render `SESSION_SECRET` 为独立高强度 Secret。
- [ ] Render `SESSION_COOKIE_SECURE=true`。
- [ ] `CORS_ORIGINS` 只包含正式 Web 来源，不使用通配符。
- [ ] `VITE_API_BASE_URL` 指向正式 API。
- [ ] Web/API 优先使用同一可注册域下的自定义域名。
- [ ] R2 Bucket 私有，API 凭据为最小权限。
- [ ] 已轮换本地日志中暴露过的 R2 凭据。（生产操作）
- [ ] Pages 构建环境不包含数据库、会话或 R2 Secret。

## 数据与恢复

- [ ] 已确认 Neon 备份能力、保留周期和负责人。
- [ ] 已记录 RPO、RTO。
- [x] 已完成本地 Compose 数据库隔离恢复演练。
- [x] 本地恢复后迁移版本、核心表数量和结算账单数量一致。

## 云端冒烟

- [ ] `/api/healthz` 返回 200。
- [ ] `/api/readyz` 返回 200。
- [ ] 登录、刷新恢复、退出和过期会话正常。
- [ ] 四角色页面显隐与 API 权限一致。
- [ ] 商品图片上传、读取和删除正常。
- [ ] 商品、采购、销售、费用、结算形成完整闭环。
- [ ] 五类报表查询正常。
- [ ] CSV 导出、时间格式和审计记录正常。

## 发布与回滚

- [x] 所有本地 typecheck、test、build、db:check、Compose 构建和生产依赖审计通过。
- [ ] 形成可追溯 Git 提交和发布版本。（需用户指令）
- [ ] 记录当前生产版本和上一可用版本。
- [ ] 数据库迁移前完成备份。
- [x] 回滚步骤包含应用版本、环境变量和数据库恢复边界。
- [ ] 已获得正式部署明确确认。（生产操作）

## 回滚执行顺序

1. 任一健康、权限、Cookie、R2、金额或迁移检查失败，立即停止继续发布和业务写入。
2. Render 与 Pages 回退到上一可用部署，恢复发布前保存的环境变量版本。
3. 数据库迁移不自动反向执行；如数据受到影响，使用发布前 Neon 备份恢复到隔离分支或项目，核对迁移和核心数据后再切换 `DATABASE_URL`。
4. 回退后重新检查健康接口、登录会话、核心业务闭环、报表和 CSV，再决定是否恢复服务。

## 停止条件

出现健康检查失败、权限越权、迁移异常、Cookie 无法恢复、R2 失败或核心金额不一致时，停止发布并回退到上一可用版本。
