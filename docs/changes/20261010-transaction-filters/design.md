# 交易列表排序与筛选

## 目标、范围与风险

风险等级：L1，已有列表页局部查询和交互调整。

目标：销售记录按售出时间统一倒序，提供商品名称关键词和批次售出人员多选筛选，方便定位普通销售及快速售出。沿用现有页面结构、卡片、操作与 Vant 筛选样式，属于已有页面局部控件增加，无需新页面原型。

影响范围：`apps/web/src/pages/TransactionsPage.vue`、使用手册和本变更记录。继续使用现有销售、快速售出、费用和批次成员 API；不修改接口、权限、数据库结构、库存、撤销或结算规则。

## 实现与验收契约

- 合并普通销售和快速售出，按 `occurredAt` 倒序；同一售出时间按 `createdAt` 倒序，再按来源和业务 ID 稳定排序。已撤销、已结账记录继续展示原有状态。
- 商品关键词实时做不区分大小写的包含匹配，忽略首尾空白；普通销售匹配商品名称、商品组、款式和展示名，快速售出匹配其完整商品组合名称。
- 售出人员从 `GET /batches/:id/members` 返回的当前批次全部人员中选择，包含暂无销售人员；按用户 ID 匹配，防止同名人员混淆。
- 多选人员之间取并集，与关键词条件取交集；没有选人时代表全部人员。
- 按用户要求采用类似 el-select 的带边框选择框和锚定菜单，通过 Vant Popover 实现，不遮罩页面；选中后显示人员名称与人数。人员下拉行为：打开时复制已应用条件，确定后应用，点击菜单外或 Escape 取消未确认修改；重置清空人员草稿，确定后恢复全部人员。
- 销售列表显示结果数量与“售出时间倒序”；清除筛选同时重置关键词和人员。区分未录入销售与筛选无结果。
- 详情、状态和撤销入口保留既有 `data-ai-id`，其他费用不受销售筛选影响。加载失败提供重试。

- Web：`npm run typecheck`、`npm run build`。
- 后端：既有 typecheck/test；隔离数据验证真实 Fastify 查询路由返回字段与当前权限行为，不连接真实数据库、不执行数据写入。
- 浏览器：390×844 与 430×932 检查跨类型时间顺序、关键词/多选/组合筛选、重置、取消、空态、详情及撤销入口、费用不受影响、长人员列表、键盘与 `data-ai-id` 唯一性；截图及自动结果存入被忽略的 `evidence/`。
- 文档：UTF-8、路径引用、`git diff --check`。

## 未验证项与残留风险

未连接真实数据库、未执行真实业务写入、未做生产部署。筛选基于现有接口一次返回的批次完整记录，未来若引入分页，需同步调整查询方式。售出人员候选项只包含当前批次成员；历史离开批次人员的销售仍可在“全部人员”中查看，但不能从当前成员菜单单独选中。

风险维持 L1：仅改已有页面的展示和本地筛选，不调整接口、SQL、权限或计算规则。用户原有工作区改动保留；未执行 Git 提交、推送或历史操作。
