# 测试计划

## 结论

验证商品组图片可安全保存和读取，并确认其只影响商品资料展示，不影响账务与库存。

- 无款式商品组可保存并沿用独立商品流程；商品组款式名重复、空名称、跨工作区、部分创建失败均拒绝且无部分数据。
- 保存商品组只创建商品资料；从商品列表选择开放批次后进入采购，采购完成直接返回库存，不创建上架记录。
- 商品组款式可有独立参考价；参考价仅用于商品资料展示，不参与采购成本、销售成交价或结算。
- 商品页以同样式的统一列表展示商品组与独立商品；商品组成员款式不得在独立商品列表重复显示。商品组与独立商品点击列表项均打开各自详情，右侧独立“采购”快捷操作才打开批次选择。输入关键字后仅在点击可见的“查询”按钮时发起请求；搜索商品组名或成员款式均能显示所属商品组。
- 商品组与单品均有详情入口和采购快捷操作；商品组详情展示成员款式与参考价，并提供独立采购快捷操作。新增采购页可直接选择商品或商品组，选择商品组后进入同页逐款采购，不必先从商品列表跳转；从独立商品快捷采购进入时直接预选该商品。
- 新建商品组初始不显示示例款式输入项；点击“新增款式”才增加空行。款式字段标签完整可见，输入区域不被标签挤压；移除未保存款式使用图标按钮。
- 商品组最多可上传五张工作区图片，第一张为列表首图；商品组详情显示全部已保存图片。商品列表中商品组和独立商品的图片右上角分别显示“商品组”和“商品”标签；无图时也保持类型可辨识。商品组图片不得被当作任意款式的图片，也不得参与库存、成本、销售或结算。
- 商品组可编辑名称、描述、图片、款式与参考价；已出现采购、上架或销售的款式拒绝删除。商品资料修改不改变已有采购、库存、上架、销售或已确认账单的名称展示和任意金额。
- 采购与上架的渠道均可通过选择器新增，新增成功后自动选中；无渠道时仍可在当前流程完成创建。
- 记录销售先选择商品组、再选择有可售库存的款式；无可售库存的商品组不展示。交易记录、创建账单和账单详情均显示商品组与款式快照。
- 组合模板按工作区隔离；模板与款式均不可重名，编辑和删除模板不影响既有商品组、采购、库存、销售和结算。
- 逐款数量与单价可不同；款式金额为单价乘数量（按分四舍五入），采购总金额为款式金额之和，成本承担合计必须守恒。
- “按数量均摊单价”按数量分配到分，并反算单价后仍保持采购总金额一致。
- 任一款式数量为空、为零或无效时，均摊操作必须提示“请填写所有款式数量”，不得写入 `Infinity`；未填写完整时采购总金额显示待填写状态。
- 采购总金额和“按数量均摊单价”位于逐款输入列表顶部。
- 采购总金额可在顶部直接输入，点击“按数量均摊单价”立即按各款数量填充单价，不经过二次弹层；手工修改逐款单价后，采购总金额自动更新。
- 添加成本承担成员后，点击“均摊成本”按人数精确分配到分，承担金额合计必须与采购总金额一致；未添加成员或采购金额不完整时给出明确提示。
- 销售按款式扣库存，独立商品行为不变；库存不足、跨批次被拒绝。
- 结算金额、成本、手续费、利润、成员净额和转账结果与改造前公式一致。
- 后端 `npm run typecheck`、`npm test`；前端 `npm run typecheck`、`npm run build`。
