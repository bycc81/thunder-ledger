# 交易默认状态筛选与销售联动撤销

## 结论与风险等级

L2：涉及财务记录、库存恢复与结算完整性。交易页销售和其他费用默认显示待结账，可下拉切换已结账/已撤销/全部。普通销售与快速售出撤销时，事务内联动撤销尚未撤销的关联其他费用，记录原因、操作者及审计；已有独立费用、单独撤销记录和账单快照保留。

## 产品与 UX 输入

现有页面增加一项单选筛选、补充现有撤销确认文案，保持页面布局、路由与主流程。属于小范围字段修复，不触发新页面原型阶段。销售筛选与关键词、售出人员取交集；两个标签页各自保存筛选值，初始待结账。记录状态只有待结账、已结账、已撤销；已结账表示已纳入阶段账单。所有卡片明确显示状态，待结账记录有写权限时提供撤销操作。费用展示发生时间与对应销售，便于核对关联范围。筛选后为空提示无匹配记录，销售清空筛选恢复关键词为空、人员全部、状态待结账。

关联费用表示依附此销售的费用，随销售作废。仍实际发生且需保留的支出应独立记录，不关联被撤销销售。确认框明确联动影响。

## 当前实现与缺口

`TransactionsPage.vue` 销售与费用展示所有记录，只有关键词和销售人员筛选。`sales-expenses.ts`、`quick-sales.ts` 各自撤销销售时没有处理关联费用。创建关联费用没有锁定销售，可能与撤销并发产生遗漏。普通销售当前在写撤销前重放库存成本账本，需移至写入撤销后，使账本排除该销售。

## 页面/API 契约

| 页面区域 | 定位 ID | 数据与操作 | 权限 |
| --- | --- | --- | --- |
| 销售筛选 | transaction-sale-status-filter | 单选 pending/settled/reversed/all，默认 pending，与关键词/人员取交集 | 批次可读 |
| 费用筛选 | transaction-expense-status-filter | 独立单选 pending/settled/reversed/all，默认 pending | 批次可读 |
| 撤销确认 | 既有各页面撤销弹窗及新增说明 ID | 销售确认说明会同步撤销未撤销的关联费用，填写原因并确认 | 服务端批次可写、批次开放 |

- 沿用销售、快速售出、其他费用 GET 接口，返回全部记录，前端计算状态过滤；合并销售来源后按售出时间/创建时间/稳定 ID 倒序。费用按发生时间/创建时间/稳定 ID 倒序。
- 沿用三个 POST reversals 接口。销售撤销成功返回 `{ ok: true, reversedExpenseCount }`；原调用保持兼容。
- 关联费用已结账返回 409 `LINKED_EXPENSE_SETTLED`，事务回滚；原销售已结账、重复撤销、权限与关闭批次错误沿用。
- 创建关联费用先锁定销售，再单独读取最新撤销/结账状态，拒绝无效、已撤销或已结账销售，防止并发撤销遗漏和锁定账单外补录。
- 页面加载/错误/只读/保存中沿用，列表空态区分无记录与筛选无匹配。已有 ID 保留，新增 ID 见 `data-ai-id-registry.md`。

## 方案与影响范围

新增共享 `apps/backend/src/transaction-reversals.ts`，固定内部映射普通/快速来源到表及关联列，查询均使用参数化值。调用者先锁定主销售，按稳定费用 ID 锁定关联费用，再重查撤销及结账状态；拒绝任何仍生效的已结账关联费用。逐条新增 expense_reversals 与 expense.reverse 审计，原因标记来源，原独立撤销记录不覆盖。销售撤销、费用撤销、库存重放在同一事务内，任一失败全部回滚。

创建关联费用使用同一主销售锁序列，与撤销/结算互斥。费用表单只提供待结账销售作为关联候选，已结账/已撤销销售不再显示。单独费用撤销继续锁定费用本身；联动撤销锁后重新读取状态避免覆盖并发单独撤销。增加防重复冲突处理。

无新迁移或环境变量；不修改金额、利润比例、认证或角色。历史已经存在的“销售已撤销但费用仍有效”不批量写入或修复，避免把实际支出误撤销；本次联动作用于新发起的销售撤销。

## 风险、回滚与边界

- 不物理删除记录，保留金额、原始关联与撤销审计。审计联动来源、销售 ID、操作者；不记录凭据或新增个人信息。
- 不修改已锁定账单；出现已结账关联费用时销售与其他费用均保持原状。
- 本地验证使用隔离 schema 和外层回滚事务，不修改现有业务数据。无需生产数据操作或清理。
- 应用回滚保留已写入撤销记录；旧版停止联动的行为需告知，优先前向修复。

## 验收标准

1. 两个标签默认待结账，可切换已结账、已撤销或全部；交叉筛选、切页状态、空态和排序正确。
2. 普通和快速销售自动撤销所有生效关联费用，独立费用/其他销售费用不动，已撤销费用原因时间不覆盖。
3. 关联费用结账、销售结账、无权限、跨批次、关闭批次、重复请求正确拒绝；失败不产生半成品。
4. 撤销后库存数量及成本账本恢复，结算候选不出现被撤销销售/费用。
5. 并发创建关联费用与撤销，以及单独费用撤销与销售撤销，不产生漏撤销或重复记录。
6. 后端 typecheck/test、前端 typecheck/build，390×844、360×800 页面截图、交互和稳定 ID 验收通过。

## 需求校准

2026-10-12 用户要求先按实际状态与展示数据梳理筛选。已只读核对本地数据库：普通销售、快速售出、费用均有待结账与已结账记录，销售与费用也有已撤销记录；未发现同时已撤销/已结账。现有本地无生效费用关联已撤销销售。用户最终确认默认展示待结账，采用“待结账、已结账、已撤销、全部”四选项。已结账通过筛选查看，“撤销”作为待结账记录的操作独立展示。

## 验收发现的结算关联口径修复

真实 PostgreSQL 页面验收发现：`availableExpenses` 以 `e.sale_id IS NULL` 判定独立费用，使其他未选中的快速售出费用自动进入本次结算。修正结算和成员明细两处 SQL：仅 `sale_id` 与 `quick_sale_id` 同时为空为独立费用，其他费用必须匹配已选交易 ID。验收覆盖结算一笔快速售出时不触碰其他待结账快速售出的费用，并且成员详情与预览一致。历史账单快照不改写。
