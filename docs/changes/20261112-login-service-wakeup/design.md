# 登录页服务唤醒入口

- 风险：L1，仅增加连接恢复交互和读取请求超时，不改变凭据校验、会话或权限规则。
- 目标：用户遇到休眠或临时 429 时，可在登录页主动尝试恢复服务并刷新验证码。
- 范围：保留登录表单及既有定位 ID，在登录按钮下增加次级按钮和状态文案。属于已有页面局部交互补充，不引入新页面或原型阶段。
- 接口：沿用前端 API baseURL 请求 `GET /api/healthz`，只接受 JSON `status: ok`；成功后调用现有验证码读取。不会提交登录、打开外部页面或自动发布。
- 边界：最多 4 次健康检查，单次最多 15 秒，失败后依次等待 10/20/30 秒，总计最多约 120 秒；验证码另有 10 秒超时。遵循可读取的 Retry-After，若等待时间超出本轮剩余预算则停止，提示稍后再试。
- 状态：初始说明、唤醒中（禁止重复点击/提交登录/刷新验证码）、验证码已恢复、服务可达但验证码失败、重试耗尽。保留输入的用户名和密码；验证码更新后清空旧验证码输入。
- 页面卸载时取消请求与等待。初始会话/验证码读取加 10 秒超时，避免入口无限等待。
- 限制：健康检查不检查数据库，也不能绕过平台限流；仅验证码成功才提示可继续登录。
- 验收：typecheck/build；390×844 和 430×932 截图、无溢出、稳定 ID；模拟 429 后恢复、持续 429、HTML 200、验证码失败、重复点击、页面离开及普通登录请求。
- 回滚：撤销本次前端变更，无数据库或部署配置变更。
