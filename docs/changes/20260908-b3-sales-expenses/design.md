# B3 技术设计：交易与费用

## 结论

B3 只实现销售、费用和撤销。用户直接记录成交，不需要先登记上架；销售保存时原子扣减库存，卖出人就是收款人。上架和渠道插件后置，不开放页面、路由或接口。

## 风险等级

`L2`。销售会改变库存，并为 B4 留下销售款和费用事实。

## 页面/API 契约

| 页面 | 主要字段 | 权限 | 接口 |
|---|---|---|---|
| 批次详情交易入口 | 销售与费用入口 | 有批次读取权 | 路由 |
| 交易页销售栏 | 商品、数量、成交总价、卖出人、成交时间、备注、撤销状态 | 有批次读取权 | `GET /api/batches/:batchId/sales` |
| 销售表单 | 商品、可卖数量、数量、成交总价、卖出人、成交时间、备注 | owner/editor | `POST /api/batches/:batchId/sales` |
| 交易页费用栏 | 费用名称、金额、付款人、关联销售、发生时间、备注、撤销状态 | 有批次读取权 | `GET /api/batches/:batchId/expenses` |
| 费用表单 | 类型、名称、金额、付款人、可选关联销售、发生时间、备注 | owner/editor | `POST /api/batches/:batchId/expenses` |
| 撤销确认 | 原因 | owner/editor | `POST .../reversals` |

- 销售不接收或展示上架关联字段；销售款固定归属卖出人。
- 金额为最多一位小数的字符串；数据库保存整数“角”；时间界面统一显示 `YYYY-MM-DD HH:mm:ss`。
- 可卖数量 = 采购数量 − 商品损坏或丢失数量 − 未撤销销售数量。销售与撤销在事务内锁定对应采购记录，避免超卖。
- viewer 只读；无读取权返回 `404`，写入越权返回 `403`，关闭批次或库存不足返回 `409`。

## 数据与后置预留

- 当前使用 `sales`、`sale_reversals`、`expenses`、`expense_reversals`。
- 先前已落地的 `listings`、`listing_status_events` 和 `sales.listing_id` 不删除，避免破坏已有本地迁移或数据；B3 不注册对应 API、不提供页面，也不由销售写入。未来接入渠道插件时再专门设计和启用。

## 验收标准

- 用户从批次详情直接进入交易，能记录销售与费用。
- 销售不选择采购来源或上架，不能超卖；撤销后库存恢复。
- 卖出人与采购付款人可不同，但销售款只记卖出人。
- 费用可关联有效销售；销售、费用撤销均保留原记录与原因。

## 风险与回滚

- 不删除任何数据库表或用户数据。若需回退，只停止使用交易页面和路由；不执行反向迁移。
- B4 才计算利润、阶段账单和谁给谁多少钱；B3 不展示这些结果。
