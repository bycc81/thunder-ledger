# 已确认账单个人明细

日期：2026-10-12。风险：L2（新增确认时快照，涉及账单数据）。

## 目标与范围

用户确认账单详情需接入前面开发的明细面板。复用现有 SettlementMemberDetailsPopup，替换成员卡片原有仅两项汇总的展开入口，不新增页面或改变结算操作流程，沿用已确认的面板布局，属于现有页面局部补齐。保留既有 data-ai-id。既有计算、金额舍入、利润比例、转账建议、调整单算法及原响应不变。库存拆分、历史数据推算和生产部署不在范围内。

## 页面/API 契约

- 账单详情每个成员的“查看计算明细”打开公共面板，展示承担成本、付款归属、费用垫付、实收销售款、利润分成及原确认结果。
- GET /api/batches/:batchId/settlements/:settlementId/members/:userId/details：沿用账单查看权限，允许批次可读成员、管理员及已关闭批次。成员按账单确认结果校验，不要求仍属于当前批次；无批次读取权限/跨批次账单/非账单成员返回404，未登录401，非法UUID400。
- 响应沿用 SettlementMemberDetails，增加 snapshotStatus（confirmed / legacy）和可选 notice。加载、失败重试、切人/关窗/换账单的过期响应隔离、按账单及人员缓存均由详情页负责。
- 面板以已确认账单结果为准，不重新计算或覆盖。确认明细来源文案与预览区分；历史缺失以提示和未知金额显示。库存跳转为当前库存参考，独立页签打开，明确不是历史库存余额。

## 数据设计与流程

新增可重复迁移025：settlement_bill_member_details，主键账单+人员，复合外键指向 settlement_member_results；version=1，details jsonb保存确认时完整人员明细（金额为两位小数字符串，含销售/费用/名称/逐笔分摊/快速商品项和关联库存消耗快照）。无历史回填。

提取现有未结账明细只读组装方法，保持现有接口语义。确认账单在现有事务内、现有行锁及校验之后读取选中销售的分摊/商品项，沿用同一个组装方法，并在成员结果写入后保存每个成员明细。保存前逐成员核对明细合计与原计算结果；若并发变化导致不一致返回409并回滚。新快照写入失败，整单回滚；不允许确认成功却遗漏明细。明细读取不调用成本账本重建/结算计算/均摊，不写业务表。

新账单 GET 只读存储的JSON快照，不读取当前销售分摊或商品名。旧账单从 settlement_bill_sales / settlement_bill_quick_sales / settlement_bill_expenses 和 settlement_member_results 构建可展示部分：销售成本、售价、手续费、人员汇总及费用/收款来源沿用原快照；逐笔本人承担/付款归属为null、分摊数组为空、快速商品项不推算。明确提示未保存历史逐笔分摊/商品项，绝不用当前分摊冒充历史。查询使用只读一致性事务。

## 迁移、回滚与风险

迁移仅新增表，不更新既有账单。先完成隔离schema重复迁移与回滚测试，再应用本地迁移使开发服务可用；生产迁移/部署需另行明确授权。本轮不提交或推送。回滚代码可保留新表，旧账单继续可读；新快照数据须保留，不删除。历史账单缺失的逐笔分摊无法可靠恢复，是明确限制。
