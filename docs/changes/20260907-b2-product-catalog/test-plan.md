# B2 测试与验收计划：商品资料、图片与商品列表

## 结论

本轮重点证明商品和图片严格隔离在当前工作区内、四种工作区角色的读写边界正确、R2 预签名直传与私有读取受控、金额与名称数据准确，以及移动端列表和表单在已确认的 UX 状态下可用。

## 验收场景

1. owner、admin、editor 在当前工作区创建名称必填、描述和参考价可选的商品；创建后列表和详情显示刷新后的资料。
2. 商品名称为空白、参考价为负数、超过一位小数或不是有效金额时，API 返回字段错误；Web 保留用户输入并显示字段反馈。
3. 未填写描述或参考价时，详情和列表显示已确认的中性文案；金额以最多一位小数的字符串准确返回。
4. 名称关键词只匹配当前工作区商品；搜索无结果时保留关键词并允许清除。
5. viewer 可读取当前工作区列表和详情，但不能创建或更新；直接调用写 API 返回 `403 FORBIDDEN`。
6. 非成员不能列举指定工作区商品；成员不能读取或更新另一工作区的商品，详情返回 `404 NOT_FOUND`。
7. 创建和更新各产生一条商品审计记录，包含操作者、工作区、动作和商品 ID，不记录完整描述或 URL。
8. 编辑者可直接上传 JPEG、PNG、WebP、GIF 且不超过 10 MB 的图片；R2 完成后图片仅在完成确认成功时变为 ready。非图片、超大、跨空间或不存在资产被拒绝。
9. 单个商品最多关联 5 张 ready 图片，第一张是列表首图；重排、解除关联、上传失败重试、详情轮播与全屏大图均符合原型。移除关联需要二次确认且不直接删除关联资源。
10. 同工作区 viewer 可获取关联图片；非成员、跨工作区成员和未登录用户不能获得短时读取 URL。签名 URL 到期后重新查询商品会换取新 URL。
11. 无商品、加载失败、请求中、保存成功和 viewer 状态均有可理解的界面反馈；无图商品显示占位而不调用资产 URL。
12. 商品入口从底部“商品”主导航进入，工作区概览保留快捷入口；四项底部导航与既有工作区、批次、成员、审计流程不回归。

## 自动化验证

实施完成后按实际改动执行：

- `apps/backend`：`npm run typecheck`、`npm test`；新增商品 API 的 Fastify/数据库集成测试覆盖角色、跨空间、校验和审计。
- `apps/backend`：`npm run db:check`；在隔离数据库执行 `npm run db:migrate`，检查新迁移版本、表、约束和索引。
- `apps/web`：`npm run typecheck`、`npm run build`；使用稳定 `data-ai-id` 进行商品主流程自动化或可复现交互检查。
- 文档与实现：UTF-8 重读，扫描 `data-ai-id` 与 [data-ai-id-registry.md](data-ai-id-registry.md) 的覆盖与重复，运行 `git diff --check`。

## 人工验收

1. 用 owner/admin/editor/viewer 账号进入同一协作工作区，确认前 3 者都有商品新建/编辑入口，viewer 仅见只读说明。
2. 用第二个工作区成员和非成员分别访问商品 URL，确认无跨空间内容或可写入口。
3. 在 390×844 与 430×932 视口检查列表、空态、搜索无结果、详情和表单：无横向滚动、遮挡、拥挤或固定保存按钮错位。
4. 验证新建、编辑、取消未保存修改、名称/金额错误和网络失败时的 Toast/字段/页面反馈；返回列表时保留搜索关键词和预期位置。
5. 验证无图占位、上传、最多五张、首图调整、移除确认、详情轮播和全屏大图均符合已确认原型。

- 已完成文档静态验证：变更目录 UTF-8、`data-ai-id` 注册表 54 项与 Web 源码覆盖检查、`git diff --check`。
- 历史迁移修复：已核对并对齐本地 `002_batch1_access`、`003_batch_members` 的校验记录；表结构与当前迁移目标一致。另发现已记录的 `001_initial` 缺少 `assets` 表，004 以幂等方式补齐该基础表后再建立 B2 表。
- R2 冒烟结果：本地 `.env` 已配置并修正 Bucket 名称后，`presign`、对象 `PUT`、`complete`、私有读取和测试资源 `DELETE` 全部返回 200，测试资源已清理。R2 Endpoint、Bucket、API Token 和服务器侧读写链路均已验证。
- 浏览器 CORS：修正 Bucket CORS 后，本地 `http://localhost:5174` 与 Pages 域名预检均返回 204，并返回允许方法和 `x-amz-*` 请求头。
- 完整 R2 冒烟已通过：预检 204、对象 PUT 200、complete 200、私有读取 200、测试资源清理 200。
- 页面实测闭环：已创建商品“日咖”，数据库确认有一张 `ready` 图片以位置 1 关联；创建审计记录存在。经 Fastify 注入读取，商品列表和详情均返回 200 及 `firstImage`，详情 `images[0].url` 也是短时私有读取地址；直接读取该资产 URL 返回 200。列表首图、详情轮播和大图预览共用这些签名地址。
- 权限实测：临时创建并清理 viewer/工作区数据后，验证同工作区商品读取 200、viewer 写商品 403、跨工作区商品读取 404、跨工作区图片 URL 读取 404。
- 图片顺序实测：在已清理的临时工作区中，验证两张 `ready` 图片创建时顺序为 `[1,2]`，更新后可重排为 `[2,1]`，移除后为 `[1]`；被移除的底层资产仍是 `ready` 且未软删除。
- 本地视觉验收：已在 390×844 和 430×932 截取商品列表，首图、标题、新建、顶栏和四项底部导航均无横向溢出、遮挡或拥挤；390×844 的详情与编辑表单截图中，轮播、大图入口、图片管理和固定保存栏均无重叠。浏览器交互探针已验证大图预览可打开/关闭、可进入编辑页且图片就绪后保存按钮可用。
- 待外部环境验收：仓库未登记可调用的 Render/Pages 已部署 URL；尚需在部署后浏览器执行 Render/Pages 联通验证。
- 残留风险：历史迁移记录异常已在本地受控数据库处理；生产数据库必须先检查迁移记录和资产表，再在备份后执行同等修复。R2 的浏览器 CORS、实际 Token 权限与短时 URL 行为只能在 Pages 或本地真实浏览器环境验证；永久密钥不得出现在前端、日志或仓库。
