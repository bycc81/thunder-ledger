# ThunderLedger 产品路线图

## 路线图原则

- 先冻结业务边界，再按批次实现和验收。
- 每个批次完成后暂停，记录验证结果，再进入下一批。
- Markdown 是维护和评审的事实来源，HTML 是同内容的浏览看板。
- 不跨批次实现未验收功能。

## 阶段总览

| 批次 | 目标 | 主要交付 | 前置条件 | 验收门槛 |
|---|---|---|---|---|
| 0 | 需求与架构冻结 | 需求、路线图、架构图（MD/HTML） | 无 | 文档一致，边界和规则无歧义 |
| 1 | 账户、空间与权限 | 用户、邀请、空间、角色、批次参与人 | 批次 0 | 隔离和权限测试通过 |
| 1.1 | 注册与账号管理 | 邀请链接注册、已有账号加入、账号状态与密码维护 | 批次 1 | 账号开通、权限与会话失效通过 |
| 2 | 商品、图片与库存 | 商品、R2 资源、库存批次、成本 | 批次 1 | 图片权限和库存不变量通过 |
| 3 | 销售与费用 | 销售记录、卖出人、费用 | 批次 2 | 销售库存联动和费用归属通过 |
| 4 | 协作台账与结算 | 移动平均成本流水、阶段账单、采购更正、结算调整单、结账锁定 | 批次 3 | 订单结账闭环、调整单和不可变账单通过 |

## 批次门禁

### 批次 0：需求与架构冻结

- 交付 `docs/product-requirements.md`。
- 交付 `docs/roadmap/product-roadmap.md` 和 `docs/roadmap/product-roadmap.html`。
- 交付 `docs/architecture/architecture.md` 和 `docs/architecture/architecture.html`。
- 不修改业务代码。

### 批次 1：账户、空间与权限

- 数据库用户、邀请、空间、成员角色和批次参与人。
- API 执行空间、批次和私有记录的数据权限。
- 完成后端 typecheck/test 与前端 typecheck/build。

### 批次 1.1：注册与账号管理

- 邀请人设置用户名，受邀人通过注册链接设置密码并加入工作区。
- 已注册账号可由工作区所有者/管理员直接加入当前工作区。
- 系统管理员可开通、停用、恢复和重置普通账号；用户可修改本人密码。
- 密码改动或账号停用后，旧登录会话在下一次受保护请求时失效。
- 当前进度：已完成并通过开发环境验收，可进入 B4。

### 批次 2：商品、图片与库存

- 商品资料、多图/封面、R2 签名访问。
- 数量库存和可选单件明细。
- 入库、售出、作废和调整形成库存流水。

### 批次 3：销售与费用

- 直接记录销售，不开发上架状态和外部链接。
- 卖出人、成交价和直接费用；销售款固定记在卖出人名下。
- 销售扣减库存，费用关联销售或批次。

### 批次 4：协作台账与结算

- 采购总额、实际付款人与成本承担记录纳入商品移动平均成本流水。
- 销售仍按商品录入，不绑定采购批次；按销售发生时的整体库存移动平均成本计价。
- 从尚未结账的销售记录中选择一笔或多笔，生成阶段账单；确认后所选销售闭环，不再重复结账。
- 成本承担由采购记录自动汇总，结算页只确认利润比例；系统生成利润、每人应收应付和转账建议。
- 有销售后的采购编辑进入“采购更正”，保留旧值、新值、原因和历史；无销售时允许直接编辑。
- 已确认账单保持不变；采购更正对受影响账单生成独立的待确认结算调整单，支持逐张查看和确认。
- 销售成交时间不可修改；采购发生时间用于流水重放，历史负库存或报损关联采购时禁止更正。

### 批次 5：报表与运维能力

- 库存、销售、利润、成员贡献和待结算报表。
- CSV 导出遵循数据权限。
- 审计查询、备份和恢复演练。
- 报表、导出和审计功能已于 2026-09-16 完成开发、验证和用户验收。
- 生产备份可用性检查与隔离恢复演练转入 v1.0 上线门禁，不开放普通用户在线恢复。

### 批次 6：渠道插件与 SaaS 演进

- 稳定 `ChannelAdapter` 接口和手工适配器。
- 后续接入外部平台订单/上架同步。
- 再评估组织级多租户、套餐和计费。
- B6 是 v1.0 正式上线后的增强阶段，不是当前核心版本的上线前置条件。

## v1.0 上线门禁

当前不需要继续开发 B6。正式上线前必须完成以下事项：

1. **会话安全加固（开发与本地验证已完成，2026-09-16）**：高权限 JWT 已移出 `localStorage`，改为 HttpOnly Cookie；登录、退出、失效、来源校验和生产依赖审计已通过。正式 Pages/Render 域名下的跨域 Cookie 验证并入云端冒烟。
2. **权限回归（本地 API 与关键页面已完成，2026-09-16）**：owner、admin、editor、viewer 四角色真实 API 矩阵已通过，关键结算页面已完成 390×844 显隐验收；正式域名下仍需四角色人工页面验收。
3. **生产配置核对**：确认 Render、Cloudflare Pages、Neon、R2 的生产 Secret、HTTPS、最小权限、精确 CORS 和会话域名；优先使用同一可注册域下的 Web/API 自定义域名，避免第三方 Cookie 策略导致会话失效。生产凭据不得进入 Git、日志或前端构建。
4. **备份与恢复演练（本地已完成，2026-09-16）**：本地 PostgreSQL custom-format 备份已成功恢复到隔离容器，迁移签名、核心表数量和结算账单一致；仍需确认 Neon 备份能力、保留周期、负责人和 RPO/RTO。
5. **预发布与云端冒烟**：在正式生产配置下验证 `/api/healthz`、`/api/readyz`、登录、图片上传读取、核心业务闭环、五类报表和 CSV 导出。
6. **发布与回滚准备**：形成可追溯 Git 提交和发布版本，保留上一可用版本，记录迁移、回滚步骤，并在执行生产部署前获得用户明确确认。

以上门禁全部通过后即可发布 v1.0；无需等待 B6。
