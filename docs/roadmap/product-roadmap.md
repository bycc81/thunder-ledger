# ThunderLedger 产品路线图

## 路线图原则

- 先冻结业务边界，再按批次实现和验收。
- 每个批次完成后暂停，记录验证结果，再进入下一批。
- Markdown 是维护和评审的事实来源，HTML 是同内容的浏览看板。
- 不跨批次实现未验收功能。

## 阶段总览

| 批次 | 目标 | 主要交付 | 前置条件 | 验收门槛 |
|---|---|---|---|---|
| 0 | 需求与架构冻结 | 需求、路线图、架构图（MD/HTML） | 无 | 文档一致，边界和规则无歧义 |
| 1 | 账户、空间与权限 | 用户、邀请、空间、角色、批次参与人 | 批次 0 | 隔离和权限测试通过 |
| 2 | 商品、图片与库存 | 商品、R2 资源、库存批次、成本 | 批次 1 | 图片权限和库存不变量通过 |
| 3 | 上架、销售与费用 | 手工渠道、销售流水、收款人、费用 | 批次 2 | 销售库存联动和费用归属通过 |
| 4 | 协作台账与结算 | 出资、成本分摊、公共收入池、结算锁定 | 批次 3 | 结算示例和不可变快照通过 |
| 5 | 报表与运维 | 报表、导出、审计、备份恢复 | 批次 4 | 数据一致性和恢复演练通过 |
| 6 | 渠道插件与 SaaS 演进 | ChannelAdapter、多租户预留 | 批次 1-5 稳定 | 不改变核心台账模型 |

## 批次门禁

### 批次 0：需求与架构冻结

- 交付 `docs/product-requirements.md`。
- 交付 `docs/roadmap/product-roadmap.md` 和 `docs/roadmap/product-roadmap.html`。
- 交付 `docs/architecture/architecture.md` 和 `docs/architecture/architecture.html`。
- 不修改业务代码。

### 批次 1：账户、空间与权限

- 数据库用户、邀请、空间、成员角色和批次参与人。
- API 执行空间、批次和私有记录的数据权限。
- 完成后端 typecheck/test 与前端 typecheck/build。

### 批次 2：商品、图片与库存

- 商品资料、多图/封面、R2 签名访问。
- 数量库存和可选单件明细。
- 入库、售出、作废和调整形成库存流水。

### 批次 3：上架、销售与费用

- 手工渠道、上架状态和外部链接。
- 销售人、收款人、成交价和直接费用。
- 销售扣减库存，费用关联销售或批次。

### 批次 4：协作台账与结算

- 采购总额、出资、商品成本分摊。
- 销售进入公共收入池，按收益比例分配。
- 结算预览、确认锁定、调整单和历史快照。

### 批次 5：报表与运维能力

- 库存、销售、利润、成员贡献和待结算报表。
- CSV 导出遵循数据权限。
- 审计查询、备份和恢复演练。

### 批次 6：渠道插件与 SaaS 演进

- 稳定 `ChannelAdapter` 接口和手工适配器。
- 后续接入外部平台订单/上架同步。
- 再评估组织级多租户、套餐和计费。
