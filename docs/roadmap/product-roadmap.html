ThunderLedger 产品路线图

个人经营账本 + 协作空间，按批次实现、按验收推进。

批次 0：需求与架构冻结版本 v1.0风险 L2

路线图原则

先冻结边界需求、权限、结算口径先形成事实来源。
分批交付每批完成验证后暂停，再进入下一批。
可插拔演进外部渠道通过适配器扩展，不侵入核心台账。

批次门禁

批次交付范围验收门槛状态

B1用户、邀请、空间、成员角色、批次参与人。隔离、角色和 API 权限测试通过。待开始
B2商品资料、图片、库存批次、成本流水。图片权限、库存数量和成本不变量通过。待开始
B3手工渠道、上架、销售、收款人、直接费用。销售扣库、不同成交价和费用归属通过。待开始
B4共同采购、出资、收入池、结算快照和调整单。平分场景、转账额归零、锁定不可覆盖。待开始
B5报表、CSV、审计查询、备份恢复。报表一致性、权限导出和恢复演练通过。待开始
B6ChannelAdapter、外部平台同步、多租户预留。不改变核心商品、库存、销售和台账模型。后置

当前基线

仓库已有认证基础、R2 资源接口、PostgreSQL migration 和前后端骨架；商品、库存、销售、台账和结算将在后续批次按门禁实现。
